Read this first

The book’s real subject is contracts between layers.

You start with NAND, a gate that outputs 0 only when both inputs are 1. You finish with games written in a Java-like language. The path between them is not a pile of trivia. It is a series of small, testable interfaces.

Each layer answers two questions: What does this module promise? and How can I build that promise using only the layer below? Once the implementation works, you put it back in the box and use its interface.

How to use this guide. Read the main text in order. Open the “Implementation notes” only when you want more detail. The examples are deliberately small; the book’s projects are where you prove the ideas by building them.

Chapter 1 · 0:00–3:00

Boolean logic: one gate is enough

3 min

NAND is functionally complete: any Boolean function can be built from NAND gates alone. Everything else is composition.

A combinational chip is just a function of its current inputs. Give it the same bits, get the same output. A truth table specifies that function. An HDL file describes a wiring diagram that implements it.

The first useful construction is an inverter. Tie NAND’s two inputs together: Not(x) = Nand(x, x). Then And(x, y) = Not(Nand(x, y)). With Not and And, De Morgan’s laws give you Or. From there, every Boolean function is within reach.

HDL is declarative, not a list of time-ordered statements. The lines under PARTS describe connected parts. Reordering them does not change execution order; there is no execution order. Named internal pins are the wires.

Two parts you will reuse everywhere

  • Multiplexer (Mux): chooses one input. Think “hardware if/else for data.”
  • Demultiplexer (DMux): routes one input to one output and zeros the other. Think “select a destination.”

Multi-bit chips repeat one-bit logic across a bus. Multi-way chips use several selector bits. The project builds Not, And, Or, Xor, Mux, DMux, and their multi-bit or multi-way variants.

Implementation notes: from truth table to chip

For each truth-table row whose output is 1, AND together each input or its negation. OR those row terms. This disjunctive normal form proves that any truth table can become a circuit. It may be huge, so Boolean simplification matters: fewer gates usually means lower cost, energy, and delay.

Test small chips exhaustively. For larger ones, use targeted input scenarios and compare actual outputs with a known-good file. A built-in chip gives the same interface with a software implementation, so you can keep building higher layers before every lower layer is complete.

↳

Keep this: an interface hides an implementation. NAND is only the first place the book uses that idea.

Chapter 2 · 3:00–6:00

Arithmetic: addition does the heavy lifting

3 min

Bits become numbers by convention. Two’s complement makes signed subtraction reuse the same adder as unsigned addition.

An n-bit word holds one of 2n patterns. For unsigned integers, those patterns mean 0 through 2n−1. For signed integers, two’s complement uses the range −2n−1 through 2n−1−1. Negate a value by flipping every bit and adding 1.

Example in 4 bits. 0101 is 5. Flip it to 1010, add 1, and get 1011 = −5. Then 7 + (−5) produces 0010 after the final carry is discarded. Fixed-width arithmetic is arithmetic modulo 2n.

From one bit to an ALU

  • A half-adder adds two bits: sum = a Xor b, carry = a And b.
  • A full-adder adds two bits plus an incoming carry.
  • A 16-bit adder chains sixteen full-adders, passing carry from right to left.

The Hack ALU does not hard-wire eighteen separate operations. It transforms its inputs, chooses addition or bitwise AND, then optionally negates the result. Six control bits specify those micro-operations.

For example, control bits zx nx zy ny f no = 00 11 1 0 leave x alone, turn y into −1, add, and leave the result alone: x − 1. The ALU also emits zr and ng, which the CPU later uses for conditional branches.

Implementation notes: what “overflow” means here

The basic adder discards the carry beyond the word width. That is correct modulo arithmetic, but it does not distinguish every signed-overflow case. The book’s contract is simple: the low n bits are the result.

The chained adder is called a ripple-carry adder. Its worst-case delay grows with word width because a carry may travel through every bit. Real processors use faster carry schemes. Hack also omits multiplication and division from hardware; the OS implements them later.

↳

Keep this: subtraction is addition with a cleverly chosen representation. Hardware minimalism pushes richer math into software.

Chapter 3 · 6:00–9:00

Memory: add time to logic

3 min

Combinational logic computes. Sequential logic remembers. The data flip-flop (DFF) is the primitive that separates “now” from “before.”

A DFF follows one rule: out(t) = in(t−1). At the end of a clock cycle, it commits to the input from the previous cycle. All DFFs share a master clock, so state changes happen together at cycle boundaries.

A 1-bit register adds a load control. If load=1, accept the new input; otherwise feed the old output back. A Mux makes that choice, and the DFF makes the feedback safe by delaying it one cycle.

Sixteen Bit chips make a 16-bit register. Banks of registers make RAM. For reads, multiplexers select one register’s output. For writes, demultiplexers route load to exactly one register. Addresses are selection logic, not labels physically attached to cells.

The program counter is a register with three operations: increment, load a jump target, or reset to zero. It is the small piece of state that turns a stored sequence into an executing program.

Implementation notes: why feedback is safe here

A direct combinational loop can depend on itself within the same instant. A loop through a DFF depends on the previous cycle instead. This breaks the logical circle and gives the rest of the circuit time to settle.

RAM is built hierarchically: RAM8, RAM64, RAM512, RAM4K, then RAM16K. High address bits select a lower-level bank; low bits select a register inside it. Random access means the address does not change the access contract, though real physical timing is more nuanced.

↳

Keep this: a clock plus a one-cycle delay turns pure functions into stateful machines.

Chapter 4 · 9:00–13:00

Machine language: the hardware/software contract

4 min

Hack programs use three names: D is a data register, A is an address/data register, and M is the RAM word currently selected by A.

Hack is a 16-bit machine with separate instruction memory (ROM) and data memory (RAM). Every instruction is either an A-instruction or a C-instruction.

FormMeaningBinary layout
@valueSet A to a 15-bit value. This also selects RAM[A].0vvvvvvvvvvvvvvv
dest=comp;jumpCompute with the ALU, optionally store, optionally jump.111accccccdddjjj

The C-instruction’s three fields answer three questions. comp: what should the ALU compute? dest: where should the result go among A, D, and M? jump: should the next instruction come from ROM[A] instead of PC+1? Both dest and jump may be omitted.

Memory access usually takes two instructions: @address selects the location, then a C-instruction reads or writes M. Loading a constant also starts with @constant. A jump uses A as a ROM address instead. That dual role is compact but easy to misread.

Symbols and I/O

Labels like (LOOP) name instruction addresses. Unknown symbols like i become RAM variables, allocated from address 16. Predefined names include R0…R15, SP=0, LCL=1, ARG=2, THIS=3, THAT=4, SCREEN=16384, and KBD=24576.

The screen is memory-mapped: 512 × 256 monochrome pixels packed into 8K 16-bit words. Writing bits changes pixels. The keyboard is one memory word: it holds the current key code, or 0 when no key is pressed.

Implementation notes: decoding and pointer idioms

In a C-instruction, the a bit chooses whether the ALU’s second input is A or M. The six c bits choose the ALU operation. Three d bits independently enable writes to A, D, and M. Three j bits request a jump when the ALU result is negative, zero, or positive.

The pointer idiom is A=address followed by an operation on M. Arrays and object fields later compile to this same pattern. Avoid combining a memory reference with a jump in one C-instruction: A would be serving two conflicting purposes.

↳

Keep this: an ISA is not just syntax. It is the exact control interface the CPU must implement.

Chapter 5 · 13:00–17:00

Architecture: the fetch–execute loop

4 min

A general-purpose computer is fixed hardware running replaceable instructions. The program is stored in memory; changing it changes what the machine does.

The Hack computer joins three modules: a CPU, ROM32K for instructions, and a Memory chip that combines ordinary RAM with screen and keyboard maps. Its CPU contains the ALU plus registers A, D, and PC.

One cycle, three jobs

  1. Fetch: ROM emits the instruction at the current PC.
  2. Decode and execute: the instruction’s bits become control signals. An A-instruction loads A. A C-instruction drives the ALU and destination registers.
  3. Choose the next PC: increment by default; load A when the jump condition holds; reset to 0 when the machine resets.

The jump decision combines the instruction’s three jump bits with the ALU’s ng and zr flags. That tiny piece of Boolean logic is the bridge from arithmetic to control flow.

Data addressWhat the CPU sees
0 … 16383General-purpose RAM
16384 … 24575Screen memory map
24576Keyboard character code, or 0

Memory-mapped I/O means the CPU needs no special screen or keyboard instructions. It reads and writes addresses; external refresh logic synchronizes those addresses with physical devices.

Implementation notes: build the control, not new arithmetic

The CPU project is mostly wiring and Boolean decoding. A-instruction loading, C-instruction destinations, ALU input selection, writeM, and PC control all come from instruction bits. The ALU, registers, and PC already exist.

Hack’s separate ROM and RAM simplify single-cycle execution. A classic single-memory von Neumann machine must juggle instruction and data addresses on the same memory interface, often using separate fetch and execute stages. Real machines add caches, pipelines, and many other optimizations that Hack intentionally omits.

↳

Keep this: “running code” is a feedback loop: PC selects an instruction; instruction updates state and selects the next PC.

Chapter 6 · 17:00–19:00

Assembler: names become addresses

2 min

An assembler is a small translator plus a symbol table. Two passes solve forward references: first learn where labels point, then emit binary.

Strip whitespace and comments. For each real instruction, translate its fields. A-instructions become a leading 0 plus a 15-bit value. C-instructions concatenate 111, the computation bits, destination bits, and jump bits.

Why two passes? @LOOP may appear before (LOOP). Pass 1 counts only actual A- and C-instructions and binds each label to the next instruction’s ROM address. Pass 2 can then resolve every label. New variable symbols receive RAM addresses 16, 17, 18, and so on in first-seen order.

The clean implementation split is Parser (what the fields are), Code (their bit patterns), SymbolTable (name-to-address mapping), and a main driver. This separation returns in larger form in the VM translator and compiler.

Implementation notes: build in two stages

First support programs with numeric constants and no symbols. Then add labels and variables. Test by comparing your .hack output with the supplied assembler, and by executing it on the CPU emulator.

The Hack output format is deliberately plain: each line is sixteen ASCII 0/1 characters. Line n loads at ROM address n, counting from zero.

↳

Keep this: assemblers make code readable and relocatable by replacing human names with machine addresses.

Chapter 7 · 19:00–23:00

VM I: expressions become stack operations

4 min

The virtual machine is a deliberate midpoint: high enough to make compilation clean, low enough to translate mechanically into assembly.

A two-tier compiler splits the problem. The front end translates Jack into VM commands. The back end translates VM commands into a particular machine language. Change the target CPU and you replace the back end, not the Jack compiler.

The stack is the expression’s working memory

Infix source like (7 + 5) * 2 becomes postfix commands. Push operands, then apply operators to the stack top. Binary operations pop two values and push one result; unary operations replace one value with one result.

On Hack, the stack begins at RAM address 256. SP points to the next free stack slot, not the current top. Push means RAM[SP]=value; SP++. Pop means SP--; value=RAM[SP].

Variables become indexed segments

The VM has no variable names. The compiler maps declarations into local, argument, this, that, static, and other segments. The VM translator maps each segment plus index onto RAM.

VM segmentHack realizationPurpose
local iRAM[LCL+i]Current function’s locals
argument iRAM[ARG+i]Current function’s arguments
this i, that iRAM[THIS+i], RAM[THAT+i]Object fields and array access
pointer 0/1RAM 3 / 4Set THIS / THAT base pointers
temp iRAM 5 + i, for i = 0…7Fixed scratch space
constant iNo storageThe literal value i
static iAssembly symbol File.iFile-scoped static variables

All VM values are signed 16-bit integers. Booleans use false=0 and true=-1 (all bits set), which works naturally with bitwise operations.

Implementation notes: translation is local, state is global

A Parser classifies each VM command; a CodeWriter emits its assembly template. Test templates by hand with concrete RAM and pointer values before writing generator code. Emit the source VM command as an assembly comment to make generated code easier to debug.

The price of the intermediate layer is extra instructions. A translator can later optimize patterns such as a push immediately followed by a pop. The book prioritizes a correct, clear mapping over efficient output.

↳

Keep this: postfix evaluation removes the need for temporary expression registers. The stack encodes the expression tree’s evaluation order.

Chapter 8 · 23:00–27:00

VM II: functions are stack discipline

4 min

Calls, returns, nested functions, and recursion all work because the same global stack holds arguments, saved frames, locals, and temporary values.

Branching is simple: label marks a location, goto jumps always, and if-goto pops a condition and jumps when it is nonzero. Compilers build if and while from those primitives.

The call contract

The caller pushes n arguments and executes call f n. The VM saves a return-address label plus LCL, ARG, THIS, and THAT. It points ARG at the pushed arguments, makes LCL the new stack top, and jumps to f.

Returning copies the callee’s result to ARG[0]. From the caller’s perspective, the arguments disappear and exactly one return value replaces them. Restoring the saved pointers revives the caller’s segments. Recursion needs no special rule: each call adds another independent frame.

Startup is part of the same runtime: generated bootstrap code sets SP=256 and calls Sys.init. The OS’s Sys.init later calls Main.main.

Implementation notes: names, frames, and failure modes

Function names are global and use Class.function. Labels are function-local, so generated assembly names must include the current function. Return-address labels must be unique across the whole generated file.

The VM contract always returns a value. Void Jack functions compile to a dummy push constant 0; return; do statements discard that value. Deep recursion consumes real RAM for every frame, which is why stack overflow is a physical resource failure, not a language mystery.

↳

Keep this: function abstraction is a precise caller/callee contract implemented by saving and restoring a frame.

Chapter 9 · 27:00–30:00

Jack: a small language on purpose

3 min

Jack looks like a tiny Java, but every simplification serves the next projects: writing a compiler and an OS without hiding the important ideas.

Jack is object-based: it has classes and objects, but no inheritance. A program is one or more classes in a folder. Execution begins at Main.main. Each class has fields and static variables plus constructors, methods, and functions.

  • Constructor: allocates and initializes an object, then explicitly returns this.
  • Method: operates on a current object. Function: belongs to the class but has no current object.
  • Statements: let, do, if, while, and return.
  • Primitive types: int, char, and boolean, all represented by one 16-bit word.

Arrays and strings come from the OS library rather than being built-in runtime machinery. Array.new(length) allocates storage; arr[i] accesses it. String literals compile into a String object followed by appendChar calls.

Jack is weakly typed and has no garbage collection. Object variables hold addresses. Programmers should dispose objects when finished, usually through a class’s dispose method. There is also no standard operator precedence beyond parentheses; write parentheses when order matters.

Implementation notes: awkward syntax, easy parsing

Leading keywords such as let and do tell the parser exactly which statement follows. Explicit return and simple type rules keep the compiler small. These choices are not meant as language-design recommendations; they expose the machinery.

The OS API provides Math, Memory, String, Array, Screen, Output, Keyboard, and Sys. A Jack application can treat them as ordinary class calls while remaining unaware of allocation, bitmap fonts, pixel maps, or keyboard polling.

↳

Keep this: a high-level language is not magic added to hardware. It is a set of conventions whose runtime cost is implemented elsewhere.

Chapter 10 · 30:00–33:00

Compiler I: turn text into structure

3 min

Syntax analysis happens in two steps: tokenize characters, then recursively match tokens against a grammar.

The tokenizer removes whitespace and comments, then emits keywords, symbols, integer constants, string constants, and identifiers. The parser groups those tokens into classes, declarations, statements, and expressions.

A grammar rule such as whileStatement: 'while' '(' expression ')' '{' statements '}' is both a specification and an implementation outline. Recursive-descent parsing gives each nontrivial rule a routine with the same shape.

Each routine consumes exactly its construct and leaves the tokenizer at the next token. Jack is nearly LL(1): one current token usually selects the rule. An identifier at the start of a term needs one extra lookahead: [ means array access, ( or . indicates a call, and otherwise it is a variable.

In project 10, the parser emits XML that mirrors the parse tree. This makes structure visible before code generation exists. The same CompilationEngine routines survive in project 11; only their output changes.

Implementation notes: no giant syntax tree required

The recursive routines can emit XML or VM code as they go; they need not store a full explicit tree. That keeps the design small. It also means good error reporting is harder, and the project assumes valid source code.

A clean build order is tokenizer → statements without expressions → expressions → array syntax. The returned count from compileExpressionList becomes important later because VM calls need an argument count.

↳

Keep this: parsing is not “understanding” in a human sense. It is recovering a precise recursive structure that code generation can trust.

Chapter 11 · 33:00–37:00

Compiler II: structure becomes behavior

4 min

Code generation walks the same syntax as the parser, but now emits VM commands. Symbol tables supply meaning; the VM supplies runtime mechanics.

Names get locations

The compiler keeps two nested symbol tables: class scope for static and field, subroutine scope for local and argument. Each entry records name, type, kind, and index. Lookup checks subroutine scope first, then class scope.

Jack kindVM mappingLifetime
staticstatic 0, 1, …Program lifetime
fieldthis 0, 1, …One set per object
locallocal 0, 1, …One set per call
parameterargument 0, 1, …One set per call

Expressions become postfix

Compile the left term, then the right term, then emit the operator. The result stays on the stack. Multiplication and division become OS calls because the Hack ALU does not implement them.

Control flow becomes labels and jumps. if negates its condition and branches past the true block. while adds a backward jump. Unique generated labels keep nested statements from colliding. A do statement discards the subroutine’s return value with pop temp 0.

Objects and arrays are addresses with conventions

  • Constructor: push the number of fields, call Memory.alloc 1, then pop pointer 0 so this aligns with the new block. End with push pointer 0; return.
  • Method call: push the target object before the explicit arguments, so the callee receives it as argument 0.
  • Method entry: push argument 0; pop pointer 0 aligns this with the target object.
  • Array access: compute arr+i, pop it into pointer 1, then use that 0.

The temporary is necessary. If you set pointer 1 before evaluating the right-hand expression, a nested array access can overwrite it and lose the original destination. This is a small example of why code generation needs an evaluation-order contract, not just plausible snippets.

Implementation notes: the complete front end

The modules are JackTokenizer, SymbolTable, VMWriter, and CompilationEngine, coordinated by JackCompiler. A subroutine begins with function Class.name nVars. Void functions push a dummy 0 before returning. Constants map to false/null = 0, true = -1, and this = pointer 0.

Jack’s uniform word size, weak typing, and lack of inheritance make classes independently compilable and method binding static. Production compilers must also handle richer types, dynamic dispatch, optimization, diagnostics, and linking.

↳

Keep this: objects, methods, and arrays do not exist in the VM. The compiler creates those illusions using symbol mappings, pointer alignment, and calling conventions.

Chapter 12 · 37:00–40:00

OS: package the hardware’s rough edges

3 min

The Jack OS is a standard library written in Jack itself. It fills gaps in the hardware and gives applications clean services for math, memory, text, graphics, and input.

Its eight classes are Math, Memory, String, Array, Screen, Output, Keyboard, and Sys. This is not a modern kernel: there is no process scheduling, file system, protection, or networking. The book’s focus is the algorithms beneath familiar library calls.

Math should scale with bit width, not value

Repeated-addition multiplication takes time proportional to y. Shift-and-add multiplication takes 16 iterations for 16-bit inputs, regardless of their values. Division uses binary long division; square root uses a bounded search. All run in O(n), where n is the number of bits.

Jack has no shift operator, so the implementation uses a precomputed powers-of-two array to test bits. Addition and subtraction come from hardware; multiplication, division, and square root come from this software layer.

Memory, pixels, and text

  • Heap allocation: the basic allocator only advances a free pointer. The improved allocator keeps a linked free list, using first-fit or best-fit, and recycles deallocated blocks. Adjacent free blocks may need merging to limit fragmentation.
  • Pixel drawing: pixel (row, col) lives in word SCREEN + 32*row + col/16, at bit col % 16. Change that bit with read–modify–write; leave the other fifteen bits alone.
  • Text output: each character is an 8 × 11 bitmap. Output prints its rows into the screen map and advances a cursor. Integers first become decimal strings.
  • Keyboard input: read RAM[KBD], wait for press and release, echo the character, and handle backspace and Enter when building a line.

The bootstrapping loop closes. VM startup sets SP and calls Sys.init. Sys initializes the other OS classes, calls Main.main, and halts when the application returns. The OS is written in Jack, compiled by the Jack compiler, translated by the VM implementation, assembled into Hack binary, and executed by the hardware you began with.

Implementation notes: the deliberate escape hatch

Memory.peek and Memory.poke use Jack’s weak typing: assign address 0 to an Array reference, then access memory[address]. The compiler’s array machinery turns that into direct RAM access. It is elegant for this project and unsafe by design; real operating systems protect such privileges.

The standard mapping places the heap at RAM 2048, after the stack region. Each OS class can be tested independently because the VM emulator falls back to built-in implementations for OS functions not yet supplied by your code.

↳

Keep this: system software turns “write these bits” into “draw a line,” and “find free RAM” into “create an object.”

The 60-second recap

Follow one object all the way down.

When Jack runs let p = Point.new(2, 3), the compiler resolves p and Point.new, emits VM commands, and asks Memory.alloc for two words. The VM translator turns those commands into Hack assembly and manages the call frame. The assembler resolves symbols into binary. The CPU fetches each instruction, routes its control bits, and uses the ALU, registers, RAM, and clock to change state.

Nothing in that chain is mysterious once the contracts are visible.

The book’s core lesson: complex systems become understandable when every layer has a small interface, a known implementation strategy, and tests that connect the two.

What this first read intentionally compresses

The appendices are references for HDL, chip APIs, test scripts, character codes, and OS calls. The book’s perspective sections also point beyond Hack: transistor-level implementation, faster arithmetic, FPGA realization, richer languages, translator optimization, storage, communications, and modern OS services.
