让记忆成为计算本身

不是把历史塞进更长的 prompt，也不是先从数据库取回证据；而是把交互历史递归写入模型内部的动态矩阵状态，让后续 token 在 forward pass 中直接读取。

01

Problem definition

真正的目标：不再携带原文，仍能利用历史

MemT 的评测协议把“历史可用”与“历史文本可见”拆开：先按时间顺序写入，再在查询时移除原文。这定义了它与上下文扩展、RAG 和临时参数适配的分水岭。

Full Context

历史 token 全留在注意力上下文；保真度高，KV cache 与计算随可见历史增长。

→
DenseRAG / MemOS

历史留在外部存储；查询时检索文本证据，再交给 backbone。

→
MemT-1.0

历史成为每层动态矩阵 Mt；查询只带当前文本，记忆输出直接加到注意力输出。

Target

固定状态，持续交互

对固定配置，状态元素数不随历史长度 N 增长；每条轨迹独立初始化和更新，模型权重共享。

§4.3 · P.16
Constraint

保留 backbone 能力

原始 Pre-Attention、Attention、Post-Attention 不变；backbone 冻结，只训练记忆模块。

§2.1 / §3.3
Hard part

压缩必然有损

新信息不断改写同一状态，早期细节必须既 survive 又可区分；固定容量不等于可靠记忆。

02

High-level design

一条并行支路，把 Mt 接进 Transformer

被选中的层同时做原始注意力与记忆注意力：前者看当前文本，后者读入 step 的记忆快照。turn 结束后，另一套存储过程才把当前输入与回复写进下一状态。

论文机制

局部记忆 ≠ 持久权重更新

Mt 是每条在线轨迹独立的动态矩阵；φ 是离线训练、在线固定的记忆算法参数。二者与冻结的 backbone θb 共同构成 θt。

§2.2.1 · P.7
工程师视角

可读性来自“快照隔离”

同一 step 的所有 query 都读同一个 Mt；writer 可以分 chunk 生成 Mt+1，reader 却能独立批处理。这类似 MVCC 的 snapshot read。

机制依据 §4.2 · P.15；类比为本文解读
▶ 跑一遍 · Nano 的 40 MiB 是怎样算出来的
10 layers × 16 channels × 256 (dₖ) × 256 (dᵥ) = 10,485,760 elements
10,485,760 × 4 bytes (FP32) ÷ 2²⁰ = 40 MiB / trajectory

历史从 4K 增到 128K，上式中的四个配置项都不变，因此持久状态仍是 40 MiB；变化的是矩阵内容，不是矩阵形状。

▶ 跑一遍 · 为什么要把 erase 对称化

使用论文 Figure 11 的解析算例：D = I、无新写入，k = (1,1)ᵀ/√2，b = (0.99,0.01)ᵀ，y = e = (1,−1)ᵀ/√2。

原始 GDN-2a = b ⊙ k
y′ = y − k(aᵀy)
‖y‖: 1.000 → 1.114
最大方向增益: 1.139 > 1
Stable GDN-2u = √b ⊙ k
y′ = y − u(uᵀy)
‖y‖: 1.000 → 0.836
最大方向增益: 1.000

原式沿 k 施加校正，却用 b⊙k 计算擦除量，两个方向不共线时会放大正交分量；对称化后 read / erase 都沿 u，不再膨胀正交方向。

    05

    Design decisions

    六个关键取舍：收益来自哪里，代价藏在哪里

    每张卡片都按“问题 → 被否决方案 → 选择理由 → 代价”拆解。这里比模型结构本身更值得复用。

    把历史写成固定矩阵，而不是保留记录

    决策问题

    历史如何进入模型，同时避免状态随交互长度增长？

    被否决的备选

    Full Context；DenseRAG；MemOS / Mem0 / OpenViking / Graphiti 的显式检索；Temp-LoRA 的每历史参数适配。

    为什么这样选

    每层 Mt 提供固定形状读接口，memory attention 与原始注意力相加；历史原文退出查询上下文。

    代价 / 权衡

    保真度受损。最强 textual systems 在 LongMemEval-S、BEAM-1M 等仍明显更高；固定容量会挤压早期细节。

    对称化 GDN-2，而不是直接沿用

    决策问题

    怎样避免 erase 矩阵在非共线方向上放大状态？

    被否决的备选

    原始 GDN-2；GDN；Metis 的 token selection；以及为保证最坏情况收缩而把 half-life 限到约 5 tokens 的强衰减方案。

    为什么这样选

    令 u = √β⊙k，把擦除写成 I−uᵀu，得到非扩张映射，不必靠极短遗忘来换取稳定。

    代价 / 权衡

    稳定性不是均分提升的主因：移除 stable mechanism 仅从 46.97 降至 46.43；价值首先是递推可靠性。

    逐 token 更新，但按 turn 让状态可见

    决策问题

    如何在保留序列内修订能力的同时，让读取可批量执行？

    被否决的备选

    Turn-level（TL）聚合；生成过程中让每个 token 立即看到本 turn 的更新；whole-pack reader/writer 耦合。

    为什么这样选

    token 级递推可反复衰减并修订同 turn 关联；snapshot read 使所有 query 共享 Mt，reader 与 writer 解耦。

    代价 / 权衡

    当前 turn 的内容不会立刻进入本 turn 的回答；turn-level ablation 均分降至 40.98，说明粒度不能粗化。

    MoS：所有 expert 全写，读取时才路由

    决策问题

    如何扩展在线记忆容量，而不是只扩 backbone 参数？

    被否决的备选

    传统 sparse MoE 的 top-k 激活；MoE 式 load-balancing auxiliary loss；只增加单矩阵维度。

    为什么这样选

    E 份独立状态都处理所有 token；dense router 按 token 加权所有 readout。写负载天然均衡，无需辅助均衡损失。

    代价 / 权衡

    Dense compute 与中间激活随 E 增长。正式 Nano / Flash / Pro 全是 E=1；E2 / E4 证据来自 Nano scaling 实验。

    冻结 backbone，让 full-context teacher 教记忆

    决策问题

    没有原文的学生，如何学会像看见全文的教师一样回答？

    被否决的备选

    只做语言建模 CPT；只用 hard-label CE；在学生自己 rollout 上 on-policy 训练；同时微调 backbone。

    为什么这样选

    CPT 先用 CE 学会跨 segment 记忆，post-training 再用 Top-64 forward KL 对齐 full-context teacher；backbone 作为稳定锚点。

    代价 / 权衡

    训练依赖 teacher 与固定响应前缀，off-policy 不覆盖学生 rollout 漂移；去掉 post-training 均分跌 10.69。

    Chunked WY + complete-step windows

    决策问题

    有序状态更新与 MoS 激活，怎样不破坏大矩阵批处理？

    被否决的备选

    逐 token 小 kernel；whole-pack 一次性实体化所有 expert projection；跨 trajectory 切窗。

    为什么这样选

    chunked WY 把 rank-one 更新组成三角求解与矩阵乘；窗口保持 step 完整，反向时重算内部中间量。

    代价 / 权衡

    小窗增加 launch 与重算；输出、routing 概率、边界状态仍随 pack 增长，不能把窗口化理解成严格常量显存。

    07

    Critical reading

    最值得相信的，与最需要继续追问的

    论文已经证明“固定原生状态可以承载有用历史与程序性经验”；尚未证明“它能替代高保真检索”或“Agent 能自主完成持续进化”。

    论文自认局限
    • 固定容量限制细节保真；新旧信息在同一状态内竞争，精确 recall 仍困难。
    • Agent 框架依赖外部构建的经验库与检索质量，经验存储也引入计算成本。
    • 局部记忆与 hyper memory 如何互相固化、实例化，仍是开放问题。
    • 持续经验获取与跨任务 memory consolidation 尚未闭环。

    §7.5 / §8 · P.30–31

    工程师视角 · 追问
    • 稳定性收益与能力收益要分开：SGDN-2 的几何论证很强，但 GDN-2 ablation 的均分差距很小。
    • MoS 尚未进入发布配置：三款正式模型均 E=1，扩容收益和 dense 成本仍需在更大模型验证。
    • off-policy 蒸馏存在分布缺口：训练看固定 teacher 轨迹，部署时学生动作会改变后续环境。
    • 效率不是无条件更快：短历史 MemT 通常更慢；优势从长历史与状态复用中出现。
    ▶ 跑一遍 · O(1) 历史，不等于 O(1) 总存储

    示例规模 · 延伸演算 假设部署 1,000 条独立 Flash 轨迹，每条使用 Table 7 的 1,280 MiB 状态：

    1,280 MiB × 1,000 = 1,280,000 MiB
    = 1,250 GiB ≈ 1.22 TiB

    历史继续增加时，这个总量不变；轨迹数增加时，它仍线性增长。共享权重、当前 step KV cache 与运行时 workspace 还不在这笔账里。

    工程师视角 可以直接偷走的五个思想

    01
    Snapshot read + turn-boundary commit

    把写入的递推复杂度与读取的批处理解耦；即使不用 MemT，也适用于会话状态与事件溯源系统。

    02
    共享模型，按 trajectory 隔离动态状态

    明确 reset / restore / release 生命周期，避免跨用户、跨历史污染。

    03
    Full-context teacher → compressed-state student

    让教师示范“看到证据后该怎样回答”，而不只训练学生背标准答案。

    04
    完整语义边界上的 windowing

    窗口不跨 step / trajectory，既控制激活生命周期，又不破坏状态提交语义。

    05
    Failure → Success 的反事实经验数据

    从同一 breakpoint 恢复执行，只保留“原轨迹失败、经验介入后通过测试”的样本，直接学习经验的因果效用。

    最终判断：这是“状态接口”论文，不只是“记忆分数”论文

    MemT-1.0 最重要的贡献，是给 foundation model 增加了一个可训练、可持久化、按轨迹隔离、固定形状的在线状态接口。当前最佳工程定位不是取代 RAG，而是承接那些需要持续压缩、行为先验和程序性经验的负载；高精度事实证据仍应与显式检索组合。后半句为工程师视角建议，不是论文原结论。
