FlashAttention

不改变注意力的数学定义，改变数据在 GPU 里的旅程。用片上分块、在线 softmax 与反向重算，避免把 N×N 注意力矩阵搬进搬出 HBM，以更少 IO 换来真实墙钟加速和 O(N) 额外显存。

01 / Bottleneck, not just FLOPs

真正昂贵的，是把中间矩阵当成“必须落盘”的对象

标准注意力的计算量已经是 O(N²d)，但论文抓住的是另一层：softmax、mask、dropout 等操作常受内存访问限制，多次 HBM 往返会让理论 FLOPs 的优势无法变成墙钟时间。

论文 §2 · Algorithm 0目标：精确计算 softmax(QKᵀ)V，同时减少 HBM reads / writes
论文问题定义

给定 Q、K、V ∈ R^(N×d)，输出 O = softmax(QKᵀ)V。常见情形 N ≫ d；标准实现把 S 与 P 两个 N×N 矩阵写入 HBM，额外显存为 O(N²)。

工程师视角 · 分水岭

Reformer、Performer、Linformer 等主要改数学结构以压 FLOPs；FlashAttention 保留精确语义，改数据布局与执行方式。评价指标从“渐近复杂度”扩到“实际字节流量 + 内核边界”。

① S = QKᵀ

从 HBM 读 Q、K；把 N×N 的 S 写回 HBM。

→

② P = softmax(S)

再从 HBM 读 S；把 N×N 的 P 写回 HBM。

→

③ O = PV

从 HBM 读 P、V；写回 N×d 的 O。训练还要保存中间量。

FLASHATTENTION / ONE FUSED KERNELQKᵀ → mask → online softmax → dropout → ×V 都在片上完成；S、P 不写入 HBM。
资源论文中的 A100 示例优化含义
片上 SRAM每个 SM 192 KB；108 个 SM；估计约 19 TB/s快但小：让当前 tile 驻留并复用
HBM40–80 GB；1.5–2.0 TB/s大但相对慢：减少读写次数与字节量
执行边界kernel：HBM → registers / SRAM → compute → HBM融合减少中间值的跨内核往返

算术强度（每次内存访问对应多少算术操作）决定更可能受计算还是内存限制。FlashAttention 并没有让 O(N²d) 消失；它先消除内存受限部分，最终仍会在大 tile 或长序列下遇到计算瓶颈。

S 与 P 同时物化2 × 32 MiB = 64 MiB / head

03 / Execution trace

沿着一个 tile，走完前向与反向

点击步骤，或用左右方向键切换。关键是第 5、6 步：新块可能带来更大的行最大值，因此旧的 ℓ 与 O 必须乘上指数缩放因子，再与新块累加。

01

把大矩阵问题改写成块网格

按 SRAM 容量选择 Bᵣ、B𝚌；Q 与 O 分成 Tᵣ 个行块，K 与 V 分成 T𝚌 个列块。

发生什么

O 初始化为 0，ℓ 初始化为 0，m 初始化为 −∞。它们都在 HBM 中，大小分别是 N×d、N、N。

工程要点

块大小不是单纯越大越好：必须同时容纳 K/V、Q/O 和 S tile；论文用 B𝚌 = ⌈M/4d⌉、Bᵣ = min(⌈M/4d⌉, d) 表达容量约束。

Tᵣ = ⌈N / Bᵣ⌉　　T𝚌 = ⌈N / B𝚌⌉ Algorithm 1 · lines 1–4
02

外循环：让一个 Kⱼ、Vⱼ 块驻留片上

对每个 j，把 Kⱼ 与 Vⱼ 从 HBM 装入 SRAM。

发生什么

这一块 K/V 会与所有 Q 行块交互。K/V 的每个元素在外循环中只需载入一次，是 IO 复杂度下降的一半原因。

工程要点

外循环顺序让 K/V 获得复用；代价是 Q、O 与统计量要被多次扫描。M 越大，T𝚌 越小，扫描次数越少。

for j = 1 … T𝚌:　load Kⱼ, Vⱼ : HBM → SRAM Algorithm 1 · lines 5–6 · Theorem 2 proof
03

内循环：流式扫过 Qᵢ 与输出状态

固定 Kⱼ、Vⱼ，依次装入 Qᵢ、Oᵢ、ℓᵢ、mᵢ。

发生什么

每个 (i,j) 组合对应注意力矩阵中的一个 Bᵣ×B𝚌 tile；此前的 Oᵢ、ℓᵢ、mᵢ 总结了已经处理过的列块。

工程要点

不是为每个列块保存一份临时输出，而是维护一份可增量合并的输出状态。这也是与 Rabe & Staats 方法的重要区别。

for i = 1 … Tᵣ:　load Qᵢ, Oᵢ, ℓᵢ, mᵢ : HBM → SRAM Algorithm 1 · lines 7–8 · Appendix B.5
04

只在片上生成 Sᵢⱼ

计算缩放后的 QᵢKⱼᵀ，并在同一 fused kernel 中应用 mask。

发生什么

Sᵢⱼ 的形状只有 Bᵣ×B𝚌。它不需要覆盖整行，更不需要写入 HBM；dropout 也在片上执行。

工程要点

“没有 N×N 中间矩阵”指没有离片物化，而不是从不计算任何注意力分数。稠密版本仍计算所有必要的 score tile，FLOPs 仍为 O(N²d)。

Sᵢⱼ = τ Qᵢ Kⱼᵀ　　Sᵐᵃˢᵏᵉᵈᵢⱼ = mask(Sᵢⱼ) Algorithm 2 · lines 10–11
05

用 (m, ℓ) 合并 softmax 的“充分统计量”

先取当前 tile 的行最大值 m̃ 与指数和 ℓ̃，再和旧状态合并。

发生什么

m 保证数值稳定，ℓ 保存相对当前 m 的指数和。若新块最大值更大，旧指数和乘 e^(m−mⁿᵉʷ)，新块乘 e^(m̃−mⁿᵉʷ)。

工程要点

这是代数聚合，不是近似。合并后的 m、ℓ 与一次性对整行做稳定 softmax 所维护的统计量相同。

mⁿᵉʷ = max(m, m̃)　　ℓⁿᵉʷ = e^(m−mⁿᵉʷ)ℓ + e^(m̃−mⁿᵉʷ)ℓ̃ §3.1 · Algorithm 1 · lines 10–11
06

同步重缩放旧输出，再累加当前 PV

仅更新 ℓ 还不够；旧 O 的归一化基准也必须跟着 m、ℓ 改变。

发生什么

旧输出先乘 e^(m−mⁿᵉʷ)，当前未归一化概率块乘 e^(m̃−mⁿᵉʷ) 后与 Vⱼ 相乘，最后统一除以 ℓⁿᵉʷ。

工程要点

每处理一个列块就得到“截至目前所有列”的精确部分注意力输出。处理完最后一个列块，O 就是最终输出，无需第二次全量归一化。

Oᵢ ← (ℓⁿᵉʷ)⁻¹ [ ℓ e^(m−mⁿᵉʷ) Oᵢ + e^(m̃−mⁿᵉʷ) P̃ᵢⱼ Vⱼ ] Algorithm 1 · line 12 · Theorem 1 correctness proof
07

前向只留摘要；反向按块重建

保存 O、ℓ、m 与 RNG 状态 R。反向载入这些量和 Q/K/V/dO，重新计算 S、P 与 dropout mask。

发生什么

Pᵢⱼ = diag(ℓᵢ)⁻¹ exp(Sᵐᵃˢᵏᵉᵈᵢⱼ − mᵢ)；由 R 复现 dropout。Dᵢ 可直接写成 rowsum(dOᵢ∘Oᵢ)，避免对长度为 N 的 P、dP 做归约。

工程要点

重算增加 FLOPs，却省掉保存和读取 N×N 中间量的 IO。dK、dV 在片上累积后写出，dQ 按内循环增量更新。

DENSE / EXACT

稠密训练：所有 score tile 都算，但都不离片

代表负载为 GPT-2、序列长度 1K。路径保留完整 softmax(QKᵀ)V；反向通过重算换取线性额外显存。

  1. ① K/V 外循环装入，Q 与状态内循环扫描。
  2. ② 在片上完成 QKᵀ、mask、softmax、dropout 与 ×V。
  3. ③ 增量写回 O、ℓ、m；不生成 HBM 中的 S/P。
  4. ④ 反向利用 O、ℓ、m、R 重建中间块并求梯度。
LONG / EXACT

Path-X：16K 上下文，把“能不能跑”变成“能训练”

更多 token 带来更多列块与扫描，但显存中的额外状态仍随 N 线性增长。论文在 Path-X（16K）上报告 61.4% accuracy，首次让 Transformer 超过随机表现。

  1. ① Q/K/V 仍以 N×d 存在，输入输出规模线性。
  2. ② 外循环次数增加；N×N score 仍只以 tile 短暂存在。
  3. ③ 同一在线更新逻辑输出精确结果，无近似结构替换。
  4. ④ 训练反向继续重算；长序列最终会更受计算量约束。
BLOCK-SPARSE / APPROXIMATE

Path-256：把零块变成真正的“不加载、不计算”

预定义块掩码 Mᵢⱼ 为 0 时跳过整个 tile；非零块比例为 s。论文在 64K 的 Path-256 上报告 63.1% accuracy，下游实验使用固定 butterfly 稀疏模式。

  1. ① 块掩码在控制面决定哪些 (i,j) 组合需要执行。
  2. ② 零块不装载 Q/state，也不计算 score。
  3. ③ 非零块沿用同一 SRAM 数据面与在线更新。
  4. ④ HBM 复杂度的二次项乘 s；这是近似注意力，不再等价于稠密全注意力。
▶ 跑一遍 · 块稀疏怎样作用于二次项
示例输入N = 4,096；假设非零块比例 s = 25%
稠密 score 网格N² = 16,777,216 个标量位置
块稀疏需计算sN² = 4,194,304；跳过 (1−s)N² = 12,582,912

05 / Design decisions

六个选择，构成论文真正的工程价值

每张卡都按“问题 → 被否决方案 → 选择理由 → 代价”展开。这里没有免费的加速：收益来自把成本从慢速内存移动，转移到更便宜的片上计算与状态维护。

D1

优化 IO，而不是继续只压 FLOPs

决策问题

长序列注意力慢，究竟要改数学近似，还是改硬件执行？

被否决的备选

Reformer 的稀疏／哈希、Performer 的低秩近似、Linformer 的序列压缩：复杂度可近线性，但不一定带来墙钟加速，且改变模型语义。

为什么这样选

现代 GPU 上，注意力的多个阶段受内存访问限制。保留精确注意力，同时把 HBM 流量降为 Θ(N²d²/M)，可直接服务现有模型。

代价 / 权衡

稠密 FLOPs 仍是 O(N²d)。序列足够长或 tile 足够大时，计算重新成为瓶颈；近似方法仍可能更快。

D2

分块 + 在线 softmax，而非整行归一化

决策问题

softmax 需要整行最大值与指数和，如何在看不到整行时保持精确？

被否决的备选

标准 PyTorch／Megatron 路径物化 S、P；仅把多个 elementwise 操作做朴素融合，训练时仍要保存大中间量。

为什么这样选

Milakov & Gimels 的 online normalizer 与 tiling 提供了代数分解：维护 (m,ℓ)，每个块都可精确合并，数值稳定性也保留。

代价 / 权衡

每块都要维护并重缩放状态，内核逻辑比三次矩阵流水线复杂；块容量还受 SRAM 与 head dimension 制约。

D3

增量更新一份 O，而非保存所有临时输出

决策问题

处理完每个列块后，部分结果如何跨块传递？

被否决的备选

Rabe & Staats 为每个块保留临时输出与统计量，最后再合并；K 个块意味着 K 份临时输出。

为什么这样选

每处理一个块就按新 (m,ℓ) 重缩放并更新 O，只需一份输出。论文指出这比保留 K 份临时输出进一步降低总显存。

代价 / 权衡

O、ℓ、m 在内循环中反复读写 HBM；其流量通过较大的 K/V 块与较少的 T𝚌 扫描来控制。

D4

反向重算 S/P，而非从 HBM 读回

决策问题

训练反向需要 S、P，前向不保存它们，梯度怎么算？

被否决的备选

标准 attention 与 Apex FMHA 保存并读取注意力矩阵；通用 gradient checkpointing 往往以速度换显存。

为什么这样选

QKᵀ 来自低秩输入，score tile 重算很便宜；保存 O、ℓ、m、R 就足以重建 P 和 dropout。解析化反向还用 Dᵢ = rowsum(dOᵢ∘Oᵢ) 避免长行归约。

代价 / 权衡

FLOPs 增加。短序列上未必划算：Table 7 中 N=128 时前向+反向比 Apex FMHA 约慢 4%。

D5

自定义 fused CUDA，而非停留在高层算子

决策问题

怎样确保理论上的 tile 生命周期真的不会变成隐藏 HBM 读写？

被否决的备选

纯 PyTorch／TensorFlow 算子组合缺少细粒度内存控制；Apex FMHA 虽融合前向，却仍把 softmax 矩阵存入 HBM 供反向使用。

为什么这样选

把 matmul、mask、softmax、dropout、第二个 matmul 放进一个 CUDA kernel，才能让片上中间量与 IO 复杂度分析对应到真实执行。

代价 / 权衡

每种新 attention 变体都要写低层内核，工程成本高，且未必能跨 GPU 架构直接迁移。论文把高层编译到 IO-aware CUDA 列为未来方向。

D6

块级稀疏跳过整个 tile，而非只谈稀疏率

决策问题

能否把 IO-aware 原语用于近似注意力，让稀疏真正变成墙钟收益？

被否决的备选

单纯元素级稀疏难以对齐当前数据块；Linformer、Performer 等则走另一条低秩／核近似路线，不能直接复用稠密 tile 机制。

为什么这样选

块掩码为 0 时，整个 (i,j) tile 不加载也不计算。IO 二次项直接乘非零块比例 s；实验使用可表达多种结构的固定 butterfly 稀疏。

代价 / 权衡

它不再等价于稠密全注意力；需要预定义块模式。线性 Nd 项仍在，稀疏率也不能直接兑换成等比例墙钟加速。

07 / Critical reading

真正的限制不在“是否精确”，而在“精确还要付出多少计算与工程成本”

论文自己承认 CUDA 工程、跨架构迁移和多 GPU IO 尚未解决。进一步读实验，还能看到短序列、head dimension、SRAM 容量与近似交叉点构成的实际适用边界。

论文自认 · §5

内核生产仍是瓶颈

每种新 attention 都需要新的 CUDA 实现；作者希望未来能从 PyTorch 等高层表达编译到 IO-aware 内核。

跨 GPU 不保证可迁移

实现可能依赖具体架构。A100、RTX 3090、T4 的 SRAM 与带宽不同，实测加速区间也不同。

理论最优限于单 GPU 语境

多 GPU 引入另一层互联 IO。论文把跨卡注意力与相应的 IO 分析列为未来工作。

工程师视角 · 进一步质疑

“精确”不等于“总能赢”

Table 11 里 Linformer 在 N=1,024 已快于稠密 Flash；N=64K 时稠密 Flash 仍呈二次增长。它消除的是不必要 IO，不是全部二次计算。

“更少 HBM”不等于“任何形状都快”

d=128 时块必须缩小，论文报告整体加速下降；T4 的 SRAM 更小，也对应更低收益。部署前必须按 d、N、mask、dropout 与硬件重测。

短序列的反向重算可能倒贴

Apex FMHA 在 N≤512 的对比中，Flash 前向略快、反向略慢；N=128 总时延还高约 4%。如果显存不是瓶颈，保存 P 可以是合理选择。

下界陈述要保留原命题的限定

Proposition 3 说的是：不存在能在整个 M 范围上渐近优于 N²d²/M 的精确算法；作者仍把针对 M 的更精细参数化下界留作未来工作。不要简化成“每个 M 都已证明最优”。

长上下文质量不是免费副产品

Path-X 还经历 Path-64 预训练、位置嵌入插值与额外微调；附录明确说追加微调约贡献 4 个 accuracy points。长序列是必要条件之一，不是完整训练配方。

“精确”是数学语义，不是逐 bit 承诺

分块改变归约顺序，浮点结果不应被理解为与每个基线逐位一致。论文用相同训练／验证曲线与 perplexity 来验证数值行为，而非声称 bitwise equality。

可以直接偷的思想

即使你不实现 attention，也能复用这五条

  1. 先画像字节，再画像 FLOPs。把 HBM 读写、内核边界和中间量生命周期放进性能模型。
  2. 寻找可代数合并的充分统计量。softmax 的 (m,ℓ) 让全局归约变成可流式合并，而不必近似。
  3. 保存“重建所需的最小状态”。O、ℓ、m、R 比 N×N 中间量便宜；随机 mask 可保存 RNG 状态而非所有随机数。
  4. 优先重算低成本、可再生的中间量。当生成器是低秩 QKᵀ 时，重算可能比存储与读取更便宜。
  5. 把稀疏做成硬件能跳过的单位。稀疏率只有映射到整个 tile 的加载与计算消除，才更容易兑现为墙钟收益。

读到这里，应该记住的一句话

FlashAttention 的贡献不是一种新的注意力近似，而是一套把精确注意力映射到存储层级的方法：让大中间量只在片上短暂存在，用可合并状态维持正确性，用重算把显存与 IO 换成更便宜的计算。
