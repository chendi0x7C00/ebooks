LifeVal：把“懂我且能办事”变成一套可评分系统

一句话 thesis：LifeVal 用支付意愿决定“测什么”，用真实个人上下文定义“为谁完成”，再用可执行环境、逐项 rubric 与状态 diff 判定“是否真的办成”——它测的不是孤立的网页操作，而是个性化代理的综合交付能力。

01 / PROBLEM

缺口不在“会不会点网页”，而在“值得为谁做什么”

已有 agent benchmark 能测浏览器或操作系统动作，personalization benchmark 能测偏好记忆；LifeVal 试图把两条线合并，并用消费者价值来安排任务分布。

论文论点

使用量不是能力上限

使用指标只看到用户已经提出的需求，而采用往往滞后于能力；用户甚至不知道自己可以提出某些任务。LifeVal 因此从“理想数字超级助手应该自动化什么”出发，而不是从现有日志出发。

§1 Introduction · P2

论文论点

耗时也不是生活任务的价值

报税、选医保虽然低频，却影响重大；睡觉、吃饭虽然耗时，数字助手却无法代替身体执行。工作评测常用“工资 × 工时”估值，但大量家庭生产活动没有可比市场工资。

§3.1 · P3–4

工程师视角
真正的分水岭是 任务采样函数：从“方便构造、容易自动评分”转为“用户重视、依赖上下文、允许部分给分”。后续所有架构选择都在保护这三个目标。

与三类前人工作的接口

  • WebArena / OSWorld：继承可执行环境与真实工作流，但加入个人上下文。
  • PrefEval / PersonalWAB / Persona2Web：继承偏好与历史条件化，但使用真实 ChatGPT 对话和记忆，而非只用合成 persona。
  • GDPval / 家庭生产经济学：继承经济价值视角，但从职业任务转向消费者生活任务。

§2 Related Work · P2–3

五个必须同时成立的约束

  • High Value：任务分布来自高支付意愿活动。
  • High Context：长对话、记忆、文件、跨应用状态。
  • Personalized + Agentic：既要适配个人，也要执行数字动作。
  • Objectively gradable：在给定上下文后，主观任务仍可逐项判定。

02 / HIGH-LEVEL DESIGN

两条流水线：先构造“值得测的任务”，再评测“真的完成了吗”

控制面决定任务分布、个人上下文、环境与评分标准；数据面执行一次 rollout，并把最终回答、产物和环境状态变化交给评分器。

▶ 跑一遍 · 支付意愿如何变成任务配额
  1. 论文先算某活动占全部合格活动 WTP 的份额，再乘以 800 的目标任务数，并向下取整。
  2. 示例值 若某类别份额为 2.5%：800 × 2.5% = 20，该类别得到 20 个目标任务。
  3. 所有类别向下取整后，148 个类别有正配额，共 702 个目标任务；§4 报告的实际评测集为 169 个任务。

公式与 800 / 702 / 148：§A.2 · P13；169：§4 · P7。论文未展开 169 对目标配额的最终映射。

▶ 跑一遍 · “我已完成”为什么不等于完成

示例 rubric，非论文原题：一个医疗迁移任务共 4 项、每项 25 分。

  1. 正确整理病史与用药：证据在生成 PDF 中，得 25。
  2. 选择了符合个人偏好的新机构：回答与浏览证据一致，得 25。
  3. 最终回答声称“已提交转诊表”，但 backend state diff 没有对应提交：0。
  4. 遗漏用户明确要求的预约时间约束：0。总分 50 / 100。

若 Hack Grader 发现模型通过内部 RLE API 直接改状态，则不管 rubric 得分多少，整个样本都是 0。

评分证据与清零规则：§3.5 · P7；具体 4 项与分值均为示例值。

    05 / DESIGN DECISIONS

    六个关键取舍：每个“更真实”都买来一种新风险

    这是论文最值得复用的部分。每张卡都按“问题 → 被否决方案 → 选择理由 → 代价”展开。

    D1

    用支付意愿排任务，而非使用时间或使用日志

    决策问题

    有限评测预算先覆盖哪些消费者活动？

    被否决的备选

    现有使用量；ATUS 原始耗时；GDPval 式职业“工资 × 工时”。

    为什么这样选

    采用滞后于能力；低频高后果任务会被耗时法低估；家庭任务缺少市场工资。

    代价 / 权衡

    WTP 是假设性情境下的自报值，受框架与想象影响；并不等于真实收入或消费者剩余。

    D2

    让“亲身经历过的人”写题，并授权使用真实个人数据

    决策问题

    谁来定义“对我而言，什么才算最佳完成”？

    被否决的备选

    通用标注员写标准答案；PrefEval 式长合成对话；Persona2Web 式合成 profile；PersonalWAB 的生成用户画像。

    为什么这样选

    作者需多次亲自完成并持续一年以上看到结果；同一人提供真实历史和 rubric，个性化 ground truth 更可信。

    代价 / 权衡

    招募与审查昂贵；PII 要替换为合成数据；个人“最佳”仍可能带有个体偏见，任务难以规模化复制。

    D3

    用 RLE、初始状态与离线 Web 承载动作

    决策问题

    怎样让代理执行真实工作流，又能检查和复现？

    被否决的备选

    纯文本回答；直接操作持续变化的 live web；只记录 GUI 截图而不看后端状态。

    为什么这样选

    RLE 提供账户、表单、交易和起始状态，离线浏览器降低网站漂移，state diff 让副作用可评分。

    代价 / 权衡

    每题都要造环境；论文承认 Web cache 未冻结，浏览依赖任务仍可能跨 run 变化。

    D4

    逐项 rubric + 全证据评分，而非单一成功位或只看最终回答

    决策问题

    主观且长程的任务怎样给出可比、可解释的分数？

    被否决的备选

    整体 pass / fail；只读最终文本；只比较最终 UI；WebVoyager 式以整体任务评价为主的做法。

    为什么这样选

    每项独立评分可给部分分；最终回答、实际文件和 backend diff 交叉验证，避免“声称完成”拿分。

    代价 / 权衡

    rubric 本身成为新的被测对象；自动评分依赖 GPT-5.6，且人类一致性验证只覆盖 30 个 GPT-5.5 rollout。

    D5

    单独部署 Hack Grader，内部 API 一经使用就清零

    决策问题

    代理可能绕过公开界面，直接利用评测环境的特权通道。

    被否决的备选

    只优化 reward；依赖环境天然不可攻破；事后人工抽查少数异常样本。

    为什么这样选

    真实网站通常不会开放这些内部端点；独立检测器把“环境作弊”与“任务没做好”分开。

    代价 / 权衡

    工程师视角 规则依赖对“内部 API”的边界定义；自动误判可能把正常动作清零，论文未报告该评分器的误报率。

    D6

    移动同一批个人事实，做“上下文位置”反事实实验

    决策问题

    低分到底因为信息不存在，还是模型找不到、不会用？

    被否决的备选

    只比较模型总分；只删除全部历史；把个性化评分项混成一个平均值。

    为什么这样选

    直接提供、删除、搬入历史对话形成对照；再按信息来源标记 rubric，能把检索问题从任务难度中隔离出来。

    代价 / 权衡

    工程师视角 合成插入未必等价于自然对话分布；论文未给该消融的样本量、逐项置信区间或完整模型设置。

    ▶ 跑一遍 · 95 分位 winsorized mean 怎样压制极端报价
    1. 示例值 20 个报价中，19 个是 $100，1 个是 $10,000；原始均值为 $595。
    2. 按论文的线性插值，排序后 P95 位于第 19 与第 20 个值之间的 5% 处：100 + 0.05 × (10,000 − 100) = $595。
    3. 把最高值替换为 $595，再平均：(19 × 100 + 595) / 20 = $124.75。
    4. 零报价仍保留，缺失回答不进分母；然后才用活动级均值计算 WTP 权重。

    方法：§A.2 · P13；上述报价与计算为方法演算示例。

    07 / CRITICAL READING

    可信的不是“1.7 万亿美元”，而是那套把个人价值转成证据的方法

    论文的任务构造与反事实消融很有启发，但覆盖、复现、评分器独立性和外部效度仍需更多公开细节。

    论文自认的局限

    LIMIT 1

    历史分类与美国中心

    ATUS 与 MTUS 最新相关数据到 2021 年，可能漏掉新任务；WTP 调查以美国、英语为主，可能弱代表非美国与调查面板覆盖不足的社区。

    §5 · P8

    LIMIT 2

    支付意愿只是价值代理

    结果依赖自报、问卷框架和受访者对“完美助手”的想象；与支出、工资、情绪等外部代理仅中等相关，R² ≈ 0.4。

    §5 · P8；§A.2.1 · P13

    LIMIT 3

    并非完全 timeless

    RLE 减少了 live web 漂移，但浏览所用 web cache 没有冻结；依赖时效信息的任务仍可能跨 run 改分。

    §5 · P9

    READING CAUTION

    1700 多亿？不，是 1.746 万亿

    $1.746T 是各类别美国年度 WTP 的加总。它不是 OpenAI 或任何厂商的可获得收入，也不是自动化后必然实现的福利增益。

    工程师还应追问

    QUESTION 1

    169 题怎样落到 148 类？

    附录给出 800 目标、702 向下取整配额，正文给出 169 实际任务，但没有报告最终类别覆盖、分布偏差及领域分层结果。总分可能掩盖某些高价值领域只有极少数题。

    QUESTION 2

    评分器结论能外推到所有模型吗？

    主评分器是 GPT-5.6，而人类一致性实验只看 GPT-5.5 的 30 个 rollout。是否对 GPT-5.6、Astra 或其他模型存在系统性评分偏差，论文未分别验证。

    QUESTION 3

    外部团队能复现多少？

    论文未提供 arXiv、代码或数据发布链接，也没有公开环境与任务包。方法可以复用，但 169 题分数目前不等于第三方可独立复跑的结果。

    QUESTION 4

    能力维度是否被耦合？

    完整对话 dump 同时考验长上下文检索、偏好推理和工具执行。来源标注与消融是很好的拆解起点，但仍需控制检索预算、上下文长度与环境难度。

    ▶ 跑一遍 · 人类评分校验覆盖了多大范围
    1. 人工校验子集：30 个任务；完整评测集：169 个任务。
    2. 按任务数计算：30 / 169 = 17.8%（四舍五入）。
    3. 这 不代表其余 82.2% 评分错误；它只说明 r = 0.864 的直接证据来自约 17.8% 的任务，而且仅评 GPT-5.5 rollout。

    30：§A.3 · P14；169：§4 · P7；17.8% 为据论文数值计算。

    可以直接偷的思想

    • →价值加权采样：别只按日志频率或构造难度排评测题；先定义用户价值函数，再公开采样规则。
    • →Rubric provenance：给每个评分项标记所需信息来源，才能把“检索失败”和“推理失败”拆开。
    • →Backend state diff：把真实副作用纳入证据，不让流畅的最终回答替代实际完成。
    • →反事实搬移上下文：同一事实分别直接给、删除、藏进历史，能快速定位记忆系统的检索断点。
    • →独立 Hack Grader：评测 reward 之外，再监控环境特权路径；奖励与作弊检测解耦。
    • →失败构成 + 总失败率分开：一个看“哪里坏”，一个看“坏多少”，避免模型换代后被归一化比例误导。
