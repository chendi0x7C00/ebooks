01总览：一张分层图

DeepSeek Harness（命令行 dsh）的定位是 agent harness——不是 Agent 产品本身，而是驱动 Agent 的运行时骨架：会话管理、提示词装配、工具执行、模型适配、持久化、沙箱、审批、Web UI，全部以插件形式挂在一棵 Cordis 插件树上。它的第一性原理写在根 AGENTS.md 里：everything is a plugin。

整个系统没有"特权核心"。所谓核心脊柱（session / tools / agent-loop）也只是第一批被挂载的插件——可以被 patch 层整体替换。这带来一个直接的工程后果：扩展 dsh 不需要改代码，改组合即可。

02核心抽象

2.1 Cordis 五要素

dsh 的一切都建立在 vendored Cordis 之上（源码钉在 vendor/，上游是 cordiverse/cordis）。它的模型可以压缩成五个概念：

概念语义dsh 中的体现
Plugin实现 Service 的对象：可以是带 inject/apply(ctx) 的函数，也可以是 Service 子类。每个 @deepseek-ai/dsh-* 包默认导出一个插件。
Context服务仓库。服务以稳定键 ctx.<key> 注册，消费者按键取用而非 import 具体实现。ctx.tools、ctx.llm、ctx.sessions 等约 50 个键。
inject声明服务依赖。依赖未就绪则挂载等待——启动顺序由依赖图推导，而不是手工编排。agent-loop inject 五个服务后才就绪。
Typed Events经 TS declaration merging 声明的事件，按四种模式分发：emit（观察）、waterfall（链式改写，须 next() 委托）、serial（保序）、parallel（并发）。全部拦截点：prompt 装配、请求构造、工具执行、turn 终止。
Reversible Effects注册即效果（ctx.effect()），返回 disposer；插件卸载/热重载时自动回卷。工具 schema、prompt section、adapter 全部可热拔插。
waterfall 是 dsh 最重要的扩展机制。它是 around-middleware：监听器收到 (...args, next)，调 next() 则委托下游并透传返回值，直接返回则短路。权限拒绝、请求改写、重试包装都靠短路或包裹实现。规约明确要求：waterfall listener 必须调 next()，否则即为有意短路。

2.2 Profile 与 Bundle：组合优先于代码

一个运行中的 dsh 实例 = 一棵在 boot 时由有序层叠拼出的插件树。层叠顺序固定：

# 层叠顺序（后者覆盖前者，按 row id 定位整条替换）
bundle 层（profile manifest 中 dsh.profile.bundles 列出的顺序）
  → profile 的 cordis.patch.yml
  → $DSH_HOME/cordis.patch.yml（home 级，HMR 热重载）
  → --patch 命令行覆盖
  → 派生补丁（telemetry 开关等）

Bundle 是分发单元：一个普通 npm 包，在 package.json 里声明 dsh.bundle.patch 指向一个 YAML patch 文件。dsh-base 是所有 profile 的第一层，451 行 YAML、78 个条目，涵盖模型适配器、工具集、持久化、沙箱与审批策略、设置、凭据、telemetry；dsh-web-app 在其上加 Web 应用（host 传输 + SPA + 27 个 ui-* 行），并把 24 个 agent 面插件从进程级撤下、改由 per-session preset 挂载；dsh-headless 只加 3 行：一个一次性 runner，无 server。

任何一层打印出来的 row 都可以被上层 patch 替换——dsh --profile web --dump-config 就是系统的"组合真相"。

2.3 Capability Seam：三角色能力缝

可替换能力的标准形态叫 seam，由三个角色构成，缺一不可：

Service Definition

声明接口与 ctx.<key> 的 Cordis Service（抽象类或注册表类，不是 TS interface），同时拥有词汇类型。

Service Provider

实现方。可多个并存、按配置选择。例如 ctx.shell 有 bash-local / bash-sandbox / pwsh-local / pwsh-sandbox 四个 provider。

Consumer

消费方，通常是 model-facing 工具。例如 dsh-tool-bash 只依赖 ctx.shell 抽象，不知道背后是本地还是沙箱。

设计纪律：扩展插件依赖 Service Definition，永不依赖具体 provider。换一个 provider，整个产品的行为随之切换——把 ctx.fs 与 ctx.subprocess 指向 E2B 远程沙箱，Bash、PTY、LSP 会一起迁移到远端，无需 fork 任何 provider。

2.4 Session Log：事件溯源 + "模型可见即可回放"

packages/core/session 是系统的事实源：append-only 的 SessionEvent 日志（turn/start、user/message、assistant/chunk、tool/call…），加上由日志派生的模型消息历史 deriveMessages()（带增量缓存）。

  • model-visible ⟺ logged：任何进入模型请求的内容必须能从日志重建，这是有运行时不变量（invariant）断言的。新增一种模型可见输入 = 扩展 SessionEventMap（declaration merging）。
  • Surface 机制：SurfaceManager 维护有序节点序列，compaction 用 {op:'replace', start, end} 遮蔽旧节点，从而"改写历史呈现"而不篡改日志本身。
  • 持久化是插件：session 包自己只订阅 session/event 广播；落盘由 session-persistence-jsonl / -sqlite 两个 provider 竞争同一 seam。Fork、resume、transcript、telemetry 全部从同一事件流派生。

2.5 Agent、Inbox 与 Turn/Step 循环层级

packages/core/agent 定义公共契约（Agent 接口、ctx.agents 注册表、agent/* 事件、双队列 inbox），刻意不含驱动逻辑；驱动实现 ReactLoopAgent 在 agent-loop 包，是可以整体替换的。对外交互收敛到一小组方法：

Agent 方法语义
followup(msg)排入 next-turn 队列并唤醒 driver——普通用户输入。
steer(msg)排入 next-step 队列并唤醒——在 step 边界插入引导。
inject(msg)排入 next-step 但不唤醒——上下文注入，等下一条唤醒消息一起被 claim。
cancel(cause) / whenIdle()取消与空闲等待。

循环层级有严格术语：step = 一次模型请求 + 其引发的工具执行；turn = 一批已接纳输入的排空（0..n 个 step）；round = 外层策略迭代（goal round / Ralph round）。inbox 的每次变更先记 agent/inbox/spliced 会话事件再改内存投影，因此 inbox 状态同样可回放。

2.6 Scope：per-agent 的注册可见性

packages/core/scope（纯库，约 560 行）提供横切原语：一个贡献（工具、prompt section、变量、监听器）要么是全局的，要么scoped 到某个 scope key——harness 约定"活 Agent 实例就是自己 scope 的 key"。两个机制：

  • ScopedLayers / shadowing：注册表存储分全局层 + 按 key 的 overlay 层；同名 scoped 注册遮蔽全局项（most-specific-wins）。这就是 per-agent persona 与 per-agent 工具变体的实现基础。
  • Scoped dispatch：关于某 agent 活动的事件，用该 agent 的载体（carrier）分发——未打标的监听器全局收，打标的只收自己 key（及后代）的事件。agent.ctx 上的注册同时获得可见性与生命周期。

加上 tools.restrict（按交集过滤全局工具集，被过滤的工具在 prompt 与执行两侧同时"不存在"），dsh 用同一套原语实现了 agent preset、子 agent 差异化能力、plan mode 工具门禁。

这条链上有三个值得记住的设计决策：

  • 三个域的事件分离：turn/*、step/*、user/message、assistant/*、tool/* 是持久事实；agent/* 携带活 Agent 做协调；tools/*、fs/* 等能力事件挂策略与适配器。选哪个域是大多数改动的第一个决策。
  • 被工具结果触发的新请求仍是同一 turn：turn 的边界由"还欠不欠"决定，而不是由模型调用次数决定。
  • 空 turn 也落账：pre-step 拒绝会关闭一个未耗 step 的 turn——尝试本身是可回放的事实。

6.4 脊柱之外的关键子系统

session/ 数据平面（13 包，8.4k 行）

持久化 seam（JSONL / SQLite 两 backend 持久化同一 SessionEvent 词汇）、projection（状态驱动的 fold 单元 + 持久化缓存，列表页永不加载全量日志）、log-backed 标题生成、OpenTelemetry telemetry。外加 session-query/ 组提供精确读、过滤、trace 与 SQLite 全文搜索。

subagent/（11 包，8.4k 行）

SubagentProvider.start(request) → SubagentRun 一个接口覆盖六种传输：进程内 spawn/fork、stdio JSON-RPC 的完整 harness（dsh-sdk）、ACP 外部 agent、Claude SDK、Codex app-server。可选 prepareContinuable() 表达"可持续子代理"（父→子 followup/interrupt，子→父 report）。

typert/ + api/（类型图 RPC）

构建期 generator 把 TS 类型树分析成编译器无关的 TypeGraph，发射 Zod codec + InvocationDescriptor；运行期 registry/loader 注册，api-gateway 据此把标了 @Remote 的 Cordis 服务暴露为严格校验的跨进程 RPC。Host 与 Browser 共享同一份类型真相。

sdk/ + acp/ + python/（进程外驱动）

sdk 三件套：换行分隔 JSON-RPC 2.0 协议库、stdio server 插件（每 sessionId get-or-create 一个 agent）、TS 客户端；Python SDK 是其设计孪生。acp/ 是 automation-only 的 Agent Client Protocol server，供程序化客户端创建 agent、发 prompt、按策略解决审批。

interaction/（人在回路）

approval seam（一次性权限裁决，无应答 fail-closed）、permission presets（workspace-write / danger-full-access 两档打包沙箱模式 + 审批策略）、commands（slash 人类命令，不经模型）、user-questions（ask-user 工具暂停在 provider 中立 promise 上）。

extensions/（自修改，15.3k 行）

agent 检视并挂载自己的插件：cordis-host-runner 在 vm 沙箱里跑模型写的插件代码，tool-cordis 让模型查询/安装/卸载运行时插件。pnpm run demo:cordis 演示 agent 修改自己的运行时。

09设计启示

1. 把"可替换性"做成结构，而不是约定

seam 三角色、waterfall 拦截点、effect 可逆注册，都是机制而非文档要求。"换 provider 不改 consumer"不是靠 code review 守住的，是靠 consumer 物理上 import 不到 provider 守住的。

2. 事件溯源作为单一事实源

"model-visible ⟺ logged" 一条不变量，统一了持久化、回放、fork、telemetry、UI 投影、snapshot 测试六个子系统的数据源。append-only 日志 + surface 遮蔽投影，让 compaction 可以"改写呈现"而不篡改历史。

3. 组合层是一等公民

profile/bundle/patch 分层 + --dump-config 单一组合路径，把"我的实例到底跑了什么"变成可打印、可 diff、可审计的事实。预发布期的立场很激进：foundation over blast radius——允许自由重命名，拒绝兼容 shim。

4. 工程门禁即架构文档

130+ 个 scripts：能力缝图、模块图、工具目录、事件目录全部由生成器产出并被 CI 保鲜校验；每文件 100% 覆盖率门禁、keyless snapshot 回放测试、运行时不变量注册表。架构文档不是写出来的，是生成出来且拒绝过时的。
