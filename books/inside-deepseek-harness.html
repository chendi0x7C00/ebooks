The whole machine

What must exist around a model call?

A coding agent joins a decision loop to owned effects and a reconstructable record.

Our CSV fixA user asks the agent to fix a CSV parser that splits a comma inside a quoted field.

A request needs owners

teaching model

“Fix the quoted comma bug” describes an outcome. To reach it, the runtime must admit the request, show the model the parser and test, execute a proposed edit, run the test command, and return what happened. The CSV example throughout this book is invented; every model response and command result shown in a lab is simulated.

The smallest useful model has a driver, a record, and effect providers. The driver decides when another model request is needed. The record preserves admitted input and observed outcomes. Providers perform operations that change files or reach another process. These responsibilities can fit in one program, but each needs a clear owner when cancellation or failure interrupts the work.

[c1-loop] [c1-tools] [c1-session] [c1-drain]

From obligations to modules

source fact

In this version, ReactLoopAgent supplies the default driver. It assembles a request, consumes a stream, commits an assistant message, and dispatches any tool calls. A step is one model request plus its tools. A response without tool calls completes the step; tool results usually require another step so the model can interpret them. A tool may also declare that its result concludes the turn.

The session stores events beyond displayed messages. Session.append() validates and snapshots event data before committing it. The message surface selects the recorded messages used for model history. deriveMessages() walks that ordered surface, excluding events such as turn boundaries. The driver builds the next frozen request from that derived history. A test command appearing in a model proposal therefore does not establish that the command ran; the tool result supplies that observation.

Ownership outlives the happy path

design inference

Cancellation cannot erase an edit that already reached the filesystem. The runtime can stop scheduling more work, ask active operations to stop, and preserve the outcomes it receives. This makes cancellation a coordination problem. It also explains why disposal waits for the driver before removing registrations and closing the session write handle.

A single function with direct filesystem and model calls suits a short, disposable script. Separate providers become useful when the same driver must support different execution environments or survive plugin replacement.

    Orientation / 02

    A runtime assembled from plugins

    How can a composition own what it adds?

    Profiles select the composition; scoped contexts attach registrations and cleanup to an owner.

    Our CSV fixBefore the CSV request runs, the selected profile must mount the model, tools, session, and execution services.

    Start with a lifetime

    source fact

    The CSV fix needs a particular set of services. A command line run may need no web server; a browser interface needs one. Configuration must select the services, establish their dependencies, and arrange cleanup if startup fails halfway through. A list of imports alone cannot express those lifetimes.

    DeepSeek Harness uses Cordis plugins. A plugin runs in a context, and its fiber tracks activation and effects. A fiber is the runtime instance of one plugin application. Its context exposes injected services and lets registrations belong to that instance. The profile selects a composition; it does not replace the agent driver.

    [c2-fiber] [c2-profile]

    Readiness has a policy

    version constraint

    boot() creates a root context, installs Loader, runs host preparation, mounts the root include, and awaits Loader settlement. It then audits inactive entries. An inactive required entry rejects startup; other inactive entries produce a warning while successful siblings remain active. A rejected startup disposes the partial context.

    This version identifies required startup entries through a maintained list and the bootstrap include. Optional entries may fail while the runtime remains usable. The required-failure test expects a successful sibling to be disposed when startup is rejected.

    [c2-effect]

    Attach registration to ownership

    source fact

    ctx.effect() runs its body immediately and collects the disposers it returns or yields. One composite effect unwinds its collected disposers in reverse order, waiting for asynchronous cleanup. Independent effects on a fiber may unload concurrently. Code that needs a strict dependency order must put that order inside an owned composite or explicit teardown.

    The harness adds a separate scope primitive. createScope() mounts a backing fiber and tags its context with an opaque key. Registration views can inherit ancestor layers, and scoped event receivers admit matching or ancestor listeners. A scope is useful when a standing plugin serves several agents but each agent needs removable contributions.

    Where this design earns its cost

    design inference

    For the CSV agent, removing tools while a request still uses them would create a lifetime race. Agent teardown therefore cancels the machine, waits for idle, disposes its scope, closes the session handle, and leaves the registries. Racing disposal callers share the same teardown promise. Quiescence means the owned work has finished settling.

    A fixed script can use direct constructors and one finally block. Scoped plugins help when contributions appear or disappear independently, or several agents share one service tree. A context can remain reachable as a JavaScript object after it becomes inactive and refuses new effects.

      The request path / 03

      One request becomes a turn

      When may new input change running work?

      Durable queues admit input at turn and step boundaries, while cancellation waits for active work to converge.

      Our CSV fixThe CSV fix is running when the user adds “preserve escaped quotes” or presses Stop.

      Input needs an admission point

      source fact

      A model call already in flight cannot absorb a new user sentence by changing the displayed transcript. The runtime needs a rule for when that sentence becomes part of a later request. It also needs to distinguish a new task from guidance for the task already running.

      The default driver has two pending lists. followup() sends waking input to next-turn; steer() sends waking input to next-step. inject() uses next-step without waking an idle driver. These operations append durable inbox splices. Pending input can therefore be reconstructed separately from input already admitted to model history.

      [c3-send] [c3-inbox] [c3-inbox-record] [c3-inbox-fold]

      A turn contains steps

      source fact

      The driver opens turn/start before preparing its first step. At admission it claims all next-step messages and, for a new turn, one next-turn message. It assembles the prompt and runs agent/pre-step. A rejection closes the turn as blocked. An initial empty admission closes the turn without spending a model call.

      An entered step logs step/start, requests the model, and may execute tools. Tool results usually lead to another step in that turn. Recovery can retry inside a step. The counters describe task admission, model-and-tool progress, and individual request attempts.

      [c3-turn] [c3-prestep] [c3-inbox] [c3-step]

      [c3-turn] [c3-prestep]

      Stop is a transition

      source fact

      By default, cancel() clears both pending lists and aborts the active activity. keepInbox preserves pending input, but cancellation itself does not promise to run it: a later wake can resume work after the old activity settles. A waking message arriving after abort targets the next turn, avoiding admission into a driver that is already stopping.

      The driver closes entered steps in finally and records an aborted turn with a copied, typed cause. During stream cancellation it retains nonempty text or reasoning prefixes as an interrupted assistant message. It drops incomplete tool proposals from that prefix; retaining one would require a tool result for work never dispatched.

      Choose the queue for the meaning

      design inference

      For the CSV task, “preserve escaped quotes” can steer the next step. “Review a different parser” belongs in a later turn. A strict FIFO queue is simpler when every message is an independent job. Two admission lists suit an interactive agent because users can refine work before it finishes.

      Cancellation is cooperative. An abort signal cannot reverse a completed edit. whenIdle() waits for the current activity and any replacement activity it latched. The streaming-cancellation test expects the interrupted prefix before the closing step and turn events.

        The request path / 04

        From model route to settled response

        How does a changing provider become one consistent call?

        A prepared call captures one adapter generation; stream settlement and retry preserve distinct attempts.

        Our CSV fixThe CSV agent has assembled its context, but provider settings may change while a request is being prepared.

        Resolve before committing the request

        source fact

        The CSV agent needs model limits, supported controls, and the connection that will carry its request. Reading those facts at different times risks pairing one generation’s metadata with another generation’s endpoint after a settings change.

        prepareCall() binds model resolution to an adapter registration. It resolves defaults, freezes a detached call configuration, and captures retry policy and model metadata. Its stream() entry point is one-shot: mismatched configuration or reuse raises INVALID_PREPARED_CALL. Dynamic adapters can override preparation to bind their own connection generation.

        [c4-prepare] [c4-request]

        Keep streaming separate from settlement

        source fact

        The llm/stream waterfall wraps dispatch. Listeners call next() to delegate or yield their own chunks to serve the request. At the final adapter boundary, adapter selection, construction, and iteration failures become a terminal failure chunk. Errors from middleware, consumers, and iterator cleanup remain thrown errors; treating them as provider failures would assign recovery to the wrong owner.

        BlockAssembler collects indexed deltas and completed blocks, usage, and finish metadata. The agent publishes live stream frames while consuming chunks. A successful attempt settles as assistant/message; a provider error settles as assistant/attempt before recovery is consulted. Partial output from a failed provider attempt does not become the successful assistant message.

        [c4-waterfall] [c4-stream] [c4-assembler] [c4-settle] [c4-stream-hook]

        Retry belongs to request recovery

        source fact

        A retry continues inside the same step. The loop prepares a fresh call for each attempt, so a one-shot prepared object is never reused. New preparation can observe a later registration. The retry plugin uses the captured provider policy passed with the failure; it tracks its budget by provider and policy within the step.

        Normal recovery checks the failure code and retry budget, then uses provider-requested delay or bounded exponential backoff with jitter. It appends llm/retry before waiting, then llm/retry-started after a completed wait. Cancellation interrupts the wait. Plugin disposal aborts and drains active recovery work.

          Mechanisms / 05

          A tool call becomes an effect

          Who turns a proposed tool call into an accountable effect?

          A registry resolves a tool, policies decide whether it may run, and the pipeline returns a settled result.

          Our CSV fixThe model proposes reading the CSV parser, editing quoted-field handling, and running its regression test.

          Separate permission from implementation

          source fact

          The harness resolves edit under the caller's scope, decides whether it may run, and returns an outcome even on refusal. A denied parser edit gives the next model step evidence to change its plan.

          ToolRuntime owns the shared pipeline. Its pre-execute waterfall can allow, deny, cancel, or ask for approval. // The in-memory log has no durability, replay, streaming, or production policy.
export async function run({ prompt, model, tools, signal = new AbortController().signal, limit = 8 }) {
  const log = [];
  const append = (type, data) => log.push(structuredClone({ seq: log.length, type, data }));
  const history = () => log.filter(e => ['user', 'assistant', 'result'].includes(e.type));
  let status = 'limit';
  append('user', { text: prompt });
  try {
    for (let step = 0; step < limit; step++) {
      signal.throwIfAborted();
      const request = structuredClone(history());
      append('request', { step, messages: request });
      const reply = await model(request, signal);
      signal.throwIfAborted();
      append('assistant', reply);
      if (!reply.calls.length) { status = 'completed'; break; }
      for (const call of reply.calls) {
        // Settle every proposed call, including calls skipped after cancellation.
        if (signal.aborted) {
          append('result', { id: call.id, ok: false, error: 'not started: cancelled' });
          continue;
        }
        append('call', call);
        try {
          const tool = tools[call.name];
          if (!tool) throw new Error('unknown tool');
          // Await the owner: abort alone does not prove the effect has stopped.
          const value = await tool(call.args, signal);
          append('result', { id: call.id, ok: true, value });
        } catch (error) {
          append('result', { id: call.id, ok: false, error: String(error.message ?? error) });
        }
      }
    }
    if (signal.aborted) status = 'cancelled';
  } catch (error) {
    status = signal.aborted ? 'cancelled' : 'error';
    append('failure', { message: String(error.message ?? error) });
  } finally {
    append('end', { status });
  }
  return { status, log };
}
