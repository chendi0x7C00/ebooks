先从一次上线审批说起

文档助手收到一条请求“复核三月份的发布。按当时生效的手册，这次上线需要几个人签字？请把依据存进我的草稿目录。”

把这条请求交给一个自回归模型。它把手册和问题切成词元（token），将已出现的前缀映射成内部状态，再给每个可能的下一个词元分配概率。图中的每一行是一个查询位置，阴影表示未来词元被遮住。矩阵只说明信息可以从哪里来，颜色不代表模型实际给了多少注意力。

P(y₁…yₜ | x) = ∏ᵢ₌₁ᵗ P(yᵢ | x, y₁…yᵢ₋₁)

这里 x 是输入，y 是回答。预训练用真实后续词元的负对数概率给预测计分。把概率从 0.1 提到 0.2 会降低损失，无论那段文字记载的是三月的旧规还是四月的新规。要答对上面的问题，系统还得找到对应版本、推断签字人数、核实依据，最后在获准的位置写文件。这几件事各有自己的成功条件。

01

记忆能压缩到多小？

English

给定显存，模型能读多长、又能记住多少？

文档助手读完一份手册，开始写第一个字。下一步生成时，每层都要用当前查询与历史位置的键算相关性，再按权重汇总值。重新计算整段历史很贵，于是服务端保存各层的键和值，即 KV 缓存。长度为 n 的提示，在稠密因果注意力下，每个头要考虑 n(n+1)/2 对位置。之后每生成一个 token，只增加一个位置，却仍要访问已有历史。长上下文解码时，读显存的带宽可能先于算力用尽。

单序列 KV 字节数 = 2（键和值）× 层数 × KV 头数 × 每头维度 × 已缓存 token 数 × 每元素字节数

假设模型有 32 层、32 个查询头，每头 128 维，用 BF16 缓存 32,768 个 token。分组查询注意力（GQA）让多个查询头共用一组键和值。把每层 KV 头数从 32 改成 8，这条请求要保留多少数据？

Python 3可独立运行
layers, tokens, head_dim = 32, 32768, 128
for kv_heads in (32, 8):
    size = 2 * layers * kv_heads * head_dim * tokens * 2
    print(f"{kv_heads} KV heads: {size / 2**30:.0f} GiB")

输出 32 KV heads: 16 GiB，然后是 8 KV heads: 4 GiB。

这笔账只含缓存张量。模型权重、工作区和内存分配开销另计。GQA 缩小每个位置占用的字节数，缓存仍随序列长度线性增长。

增量解码的带宽分析 · GQA 原论文

给精确回忆算一笔信息账

设模型读完 n 个独立比特后丢弃原文，只保留 b 个比特。若 b 小于 n，至少两串不同输入会落入同一状态。此时追问它们有差异的那一位，模型收到的问题和状态完全相同，至少有一串无法保证答对。这个计数论证给任意精确回忆划了一条硬边界。自然文档有重复，特定任务也未必关心每一位。于是可以进一步问，哪些信息可以压缩，哪些必须保留原文以便回查？

反过来，存下全文也只能保证位置可访问。RULER 在当时的 17 个长上下文模型上测了 13 项合成任务。许多模型在单条检索题上接近满分，把任务换成跨位置追踪和汇总后，在 32K 长度上，约半数达到了作者设定的参照线（Llama 2 7B 在 4K 时的 85.6%）。给自己的文档库测有效窗口，可以分别问“超时值在哪一页”和“按变更单及其例外条款，这个租户该用哪个超时值”，逐步拉开两条证据的位置，分别记录正确率。

固定状态与复制的理论界限 · RULER 长上下文实验 · 作者的参照分数与结果表

写入新规则后，还能查清旧事故吗？

超时配置在 4 月从 30 秒改为 60 秒。排查 3 月事故与配置今天的服务，需要两个不同答案。存档时给规则附上生效区间和来源，查询时先按目标日期选择版本，便得到一个可核验的基线。也可以微调模型吸收变更，再按月回放同一批问题，分别测新规采用率、旧规回溯率和无关规则的准确率。三项同时过线，才有证据表明模型学到了适用条件。跨会话记忆与持续更新研究已经把时间推理、知识更新和遗忘分开测量。

02

规则换了，模型还会做吗？

English

模型学会了一条规则，换个世界还能用吗？

只看落子序列，一个模型能学到多少黑白棋知识？每一步是否合法取决于棋盘上哪些格子能夹住对方棋子。同一格今天能下，换盘棋可能就不能下。Li 等人训练模型预测下一步，训练样本只记录落子坐标。他们随后固定棋谱，修改对应于某一格棋子颜色的内部激活，再用规则引擎重算假想棋盘上的合法落点。模型对下一步的预测随干预朝新棋盘的合法落点移动。这给出了很具体的因果证据，范围限于这套棋规和实验模型。后续研究保持训练数据和骨干网络相同，改用掩码扩散目标，依然能从激活中读出棋盘状态，但同类干预对落子的影响明显减弱。

Othello-GPT 棋盘干预实验 · 改变训练目标后的复现

实际评测可以把规则和组合方式分别留出。以日期计算为例，先测「顺延到工作日」和「加七天」，再让模型按指定顺序组合两步。然后替换假日表，刻意挑选会改变答案的日期，同时保留一组答案应当相同的对照。这样可以分清模型在哪一步退回了熟悉的日历。反事实任务研究发现，模型在非常规设置下仍有高于随机的表现，但相同任务采用默认规则时通常得分更高。另一些受控实验发现，强化学习能让模型在训练未覆盖的步骤组合上取得进步。能迁移多远，要看留出了哪些规则和组合。

改变默认规则 · 组合泛化实验

多给一秒，应当延长推理、并行搜索，还是检查答案？

文本思维链把中间结果写进上下文，后续步骤可以直接引用。并行采样让同一题出现几条不同解法，它的收益取决于候选的多样性和裁判的辨别力。前一步的隐藏向量也可以直接参与下一步计算。Coconut 在合成逻辑题 ProsQA 上达到 97.0% 准确率，同一实验的文本思维链为 77.5%。换成 GSM8K 数学应用题，次序反转为 34.1% 和 42.9%。实验中潜在步数由研究者预设。让模型自行判断何时停下，还需要单独验证。

Coconut 对照实验与表 1 · 按题目难度分配推理算力

假设要计算装下 n 条记录需要多少个容量为 4 的分片。下面用两份手写实现代表两个候选。可见测试只检查整除，平分时 Python 的 max 会留下第一个候选。

Python 3可独立运行
candidates = [lambda n: n // 4, lambda n: (n + 3) // 4]
visible = {0: 0, 8: 2}
held_out = {1: 1, 4: 1, 5: 2}

def passes(fn, cases):
    return all(fn(n) == expected for n, expected in cases.items())

selected = max(candidates, key=lambda fn: passes(fn, visible))
print(any(passes(fn, held_out) for fn in candidates), passes(selected, held_out))

输出 True False

可以先算出搜索能提供的最好机会。假设每次独立采样得到正确解的概率都是 0.2，八次全错的概率为 0.8⁸，至少一次正确的概率约为 83.2%。只有能认出正确解的裁判才能把这个机会兑现。多个候选共享同一种误解时，独立假设也会失效。

第一项表示候选里有解，第二项表示裁判选出的实现没过留出测试。pass@k 衡量前一件事。比较推理策略时，应固定总预算，把生成、打分和重试都算进去，并同时报告候选命中率和最终交付的正确率。如果候选命中率高、交付正确率低，应优先检查裁判丢掉了哪些好答案。用可验证奖励训练模型时也有这层区别，单元测试只能覆盖自己写进断言的条件。

03

下一份数据、下一块 GPU 该花在哪？

English

把旧手册改写一千遍，稀有的例外条款还能留下几条？

假设生成器已经完美学会一份手册的问答分布，千分之一的问题涉及紧急情况下的配置回滚。现在让它独立抽取一千道题作为下一轮教材。平均每套教材能见到一道回滚题，但一套教材里完全没有回滚题的概率有多大？

Python 3可独立运行
p = 1 / 1000
for questions in (1000, 3000):
    miss = (1 - p) ** questions
    print(f"{questions}: {miss:.1%}")

输出 1000: 36.8%，然后是 3000: 5.0%。

假如每代都丢掉旧教材，只照着本代样本估计频率，漏掉的例外下一轮就抽不到了。这个玩具模型只刻画有限抽样这一种损失。递归训练实验观察到了类似的长尾退化。另一组研究保留初始真实样本、逐代累积生成数据，在所测设置中阻止了测试损失发散。两种结果的分界在于哪些证据能留到下一代。做文档增强时，可以固定训练 token 总量，比较“替换旧题”和“保留原文、按条款分层抽题”，用人工留出的罕见条款单独验收。

递归训练中的分布尾部损失 · 保留并累积数据的对照实验

训练数据一样多，怎样衡量模型多学会了什么？

先区分独立证据量和训练时读过的总量。同一条发布说明改写十遍，能教会模型识别十种问法，发布日期仍只来自一个信源。关于“数据墙”的常见估算也有口径：2024 年一项研究按当时的增长趋势，预测训练集规模可能在 2026 至 2032 年接近公开人类文本的估算存量。这里的日期取决于增长假设。

样本效率要约定任务、输入单位和目标成绩。BabyLM 将纯文本组的语料上限分别设为一千万和一亿个英语词，在共同测试上比较学习方法。若用儿童听到的词数除以前沿模型训练的 token 数，视觉与交互经验、词元切分、需要掌握的技能都没有对齐。文档助手可以做更公平的对照：固定基座、训练步数和唯一原文的字节数，比较逐句改写与跨版本配对训练。评测专用的版本和问题都在训练开始前留出。

公开人类文本存量的条件预测 · BabyLM 的数据预算与评测

增加一次训练和让每个请求多想一会儿，哪笔钱更值？

预训练让许多请求共用一套语言与领域知识。后训练可以专门奖励准确引用生效版本的回答。推理时搜索可以给眼前这道难题多核对两份文档。前两项通常先付费，最后一项每次请求都要付。若各项统一按同一种成本单位核算，一个简单的生命周期预算就能暴露选择条件。

总成本 = 预训练成本 + 后训练成本 + 预计请求数 × 平均每请求推理成本

举例说，专项训练一次花 10 万元，让每次请求少花 0.01 元，在质量相同的假设下需要服务一千万次才回本。请求量、题目难度或延迟上限一变，最优点也会移动。已有实验分别测过部署请求量对模型大小的影响，以及强化学习中题目数量与每题采样次数的取舍。仍待回答的是：对一批有真实流量和错误代价的任务，能否用小规模实验预测三段预算各增加一元的收益？

把推理需求计入规模定律 · 强化学习的采样预算实验

04

怎样读懂一次计算？

English

一个特征能预测答案，怎样证明模型用到了它？

同一组神经元可以参与表示许多种信息。「叠加」给出了一种可检验的解释。如果不同特征很少同时活跃，模型就能用部分重叠的方向编码它们，代价是同时活跃时会互相干扰。这个机制在玩具网络里可以直接研究。在 Claude 3 Sonnet 上，研究者用稀疏自编码器把某一中间层的激活近似重建为少数方向的加权和，找出了能稳定响应具体内容的方向。字典大小由实验者设定。从字典里数出多少个方向，推不出模型总共掌握多少概念。

叠加的玩具模型 · Sonnet 的特征提取

检验一个解释，要先写下它对干预结果的预测。在 Claude 3.5 Haiku 的续诗实验中，模型刚读到第一行末尾的换行符，研究者就在那里的激活中找到了与第二行末词有关的特征。增强与「rabbit」有关的特征后，新的诗行会提前调整措辞，结尾出现 rabbit 或 hare。要检验这种解释能推广多远，可以换一批诗，在相同位置加入等强度的随机方向作对照，同时记录目标词概率和无关续写受损程度。模型写下的理由也能接受类似检验。在一组选择题实验里，研究者加入暗示答案的提示，再挑出模型随提示改变了选择的题。按提示类型取平均，Claude 3.7 Sonnet 和 DeepSeek R1 的思维链分别只在 25% 和 39% 的相关样本里提到它。

续诗中的电路追踪和干预 · 思维链忠实度实验

能力突然出现，还是评分把变化放大了？

训练时长和模型规模是两条不同的横轴。Grokking 最初描述的是同一网络在小型算法数据上早已拟合训练集，继续训练很久以后测试准确率才跃升。另一些「涌现」图比较的是不同大小的模型。读后一类曲线时要看纵轴。如果每个位置都要答对才能得一分，单步正确率的平滑变化会在整题得分上留下完全不同的形状。

Grokking 原始实验 · 评分指标与表观涌现

Python 3可独立运行
steps = 32
for q in (0.80, 0.85, 0.90, 0.95):
    print(f"{q:.0%} → {q ** steps:.2%}")

输出 80% → 0.08%
85% → 0.55%
90% → 3.43%
95% → 19.37%

这里假定 32 个位置独立且每步正确率同为 q，整题答对概率才等于 q**32。若只有 100 题，首行的期望满分题数还不到 0.1，大概率会被画成零。真实输出的错误往往相关。可以对同一批输出同时计算逐步得分和全题得分，给两者都标上抽样误差。再用小模型拟合趋势，把最大模型留到最后检验预测。已有研究用少量数据微调小模型，在部分基准上预判了训练算力最多高出四倍的模型能否越过能力门槛。怎样把这种预测推广到新任务和新训练方法，仍需要独立验证。

05

什么时候能信，哪些事能做？

English

模型有多大把握，才值得直接回答？

工程师问“这个接口超时后会自动重试吗？”文档助手答“会”。即使“会”是概率最高的下一个词，工程师关心的也是另一件事：对他部署的那个版本，这句话有多大概率正确？假如版本号缺失，追问一个版本号就可能消除歧义。假如版本已知而文档过期，更有用的动作是查当时生效的配置。

校准可以用一批已知答案的问题测量。把置信度在 80% 附近的回答放进一组，检查实际是否约有八成答对。即使模型对每题都报 80%，只要总体正确率恰好是八成，它也能通过这一档的校准检验，却挑不出该交给人复核的题。评估筛选能力还要同时看覆盖率（回答数除以题数）和选择性风险（已回答中答错的比例）。

把选择写成成本账就能得到一个阈值。设答对的损失为零，答错损失 10，交给可以查清事实的人复核花 1。若正确概率为 p，直接回答的预期损失是 10 × (1 − p)。达到 90% 把握时两种选择成本相同。实际部署中，人工也会出错，等待也有代价，这两个数应当重新估计。试用下面八条虚构记录，观察抬高阈值后还剩多少题。

Python 3可独立运行
records = [(.97, True), (.94, True), (.91, False), (.90, True),
           (.84, True), (.78, False), (.63, True), (.52, False)]

def report(threshold):
    kept = [ok for score, ok in records if score >= threshold]
    if not kept:
        return "覆盖 0%，风险无定义"
    coverage = len(kept) / len(records)
    risk = kept.count(False) / len(kept)
    return f"覆盖 {coverage:.0%}，风险 {risk:.1%}"

print(report(.75), report(.90), sep=" → ")

输出 覆盖 75%，风险 33.3% → 覆盖 50%，风险 25.0%

真正值得追问的是，昨天选出的阈值，到了下个 API 版本还管用吗？可以在旧版本上定阈值并冻结，然后在新版本把题目分为“有据可查”“缺版本号”“资料本身有误”，逐组画风险与覆盖率曲线。已有实验发现，模型能在部分同类任务上估计自己的正确率，换任务后校准会变差。AbstentionBench 也把前提错误、信息不足等情形分开测量。

助手读了外部文档，谁决定它能写到哪里？

给助手的任务是“读取手册，把摘要存进我的草稿目录”。手册可以改变摘要里的句子。至于写入的目标目录，授权来自用户。实现这一点的办法是，由执行器保存获准目录，在写入时检查目标与数据来源。即使模型写错摘要，这条权限规则依然可以成立。

CaMeL 展示了这种分工：系统先从可信请求生成计划，为运行时数据记录来源，再由解释器在调用工具时执行策略。在论文的 AgentDojo 设置中，受保护系统完成了 77% 的任务，对照系统完成了 84%。这两个数衡量任务完成率。安全保证来自已声明的策略及其假设。棘手的例子是“按工单里新指定的负责人转交草稿”。工单内容此时会改变接收者，系统要从哪里取得对这个新接收者的授权，同时让工作流继续？

优化器不停提高分数，作品质量为什么还会下降？

假设团队想奖励“文档中每项改动都有证据”，能自动计数的却是链接数量。复制十次同一链接，分数上升，证据没有增加。只要评分误差有规律，试的候选越多，就越有机会选中被高估的作品。即使评分程序完全确定，覆盖范围也仍由规范决定。EvalPlus 把 HumanEval 的测试用例扩充到约 80 倍后，发现了先前过关的错误代码，部分模型的排名随之改变。

在强化学习后训练中，模型根据奖励调整生成策略，使高分输出更常出现。用可执行断言给分就是一种可验证奖励。确定的断言能反复核验同一个性质，至于这个性质是否足以代表用户目标，还需要独立证据。

Gao 等用一个固定模型模拟人类偏好，再训练较小的模型给奖励。他们直接测到，继续优化代理奖励，参照模型的评分有时会下降。另一组窄任务微调实验还发现，模型在无关问答中的行为也会改变。可以把这条经验用于文档助手的回归测试：保留一批训练时不可见的文档，请评审逐条检查引用是否支持结论，同时在无关任务上比较微调前后的回答。

没有时间重做整项工作，人怎么验收？

完整重做一次数据库迁移很贵，核对一张特定表的行数可能很便宜。可扩展监督利用的正是“求解”和“检查”的成本差。一个对照实验让较弱模型充当裁判，较强的辩手可以阅读裁判看不到的原文。在这种摘录问答中，听双方陈述有助于裁判选对答案。换到没有这种信息差的任务，辩论相对直接答题的收益并不稳定。

同样要小心解读智能体的“时间跨度”。METR 的 50% 跨度把人类专家完成任务所需的时间当作横轴，用特定任务集拟合模型有一半机会成功的位置。想知道这能否预测团队里的多日任务，可以对同一批真实任务记录最终验收率、人工复核工时，以及过程中有无快速反馈。METR 后续也把可自动评分的任务和依赖判断的任务分开评估。

能为一句生成结果证明什么？

把目标缩小到“此次输出全程不含弃用字段 old_id”。固定提示、模型、解码分布和最大长度后，所有可能的输出组成一棵概率树。已经结束且合规的路径给出下界。把仍未检查的路径全部算作合规，就得到上界。下面的玩具模型至多生成两个符号：第一步以 60% 概率结束，其余进入字段分支。该分支有四分之三的概率生成 new_id，其余生成 old_id。

Python 3可独立运行
from fractions import Fraction

def bounds(good, bad):
    return f"[{float(good):.0%}, {float(1 - bad):.0%}]"

ended = Fraction(3, 5)
field = 1 - ended
valid = field * Fraction(3, 4)
invalid = field - valid
print(bounds(ended, 0), bounds(ended + valid, invalid), sep=" → ")

输出 [60%, 100%] → [90%, 90%]

BEAVER 把这种前缀搜索用于真实模型，对给定提示和可判定的安全性质计算概率界。上述 90% 只覆盖例子里定义的字段拼写。若要求变成“助手能安全完成迁移”，还得描述真实数据库的状态、工具允许的转移，以及每一步须保持的性质。怎样把这些局部保证组合起来，又让计算成本可承受，仍是开放问题。

把十四个问题带回同一条请求

回到三月的上线审批。假使助手答错了签字人数，可以给它正确版本的原文再问一次。若答案随之修正，下一组实验先检查检索和版本选择。若仍答错，就固定原文，只改变一人的签字状态，观察结论是否跟着规则变化。每次只动一个条件，才能缩小故障范围。

即使答对，验收还没有结束。把同一请求改成缺少日期，看它是否追问；给它获准的草稿目录，检查实际写入；最后让独立评审按当时生效的手册复核。找到证据、用对规则、知道何时求助、只在授权范围内行动，每一项都能单独失败，也都能设计属于自己的测试。
