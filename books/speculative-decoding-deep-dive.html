让大模型少走几步，
但不改变它说什么。

Speculative Decoding 的核心不是“用小模型替代大模型”，而是用小模型提出候选，用大模型并行验证，再用一个修正分布把随机采样的概率质量精确拼回去。它把自回归解码的串行瓶颈，转换成可并行验证的计算问题。

01 / Problem

真正的瓶颈，是串行调用次数

大模型自回归生成 K 个 token，通常要做 K 次串行解码。论文的切入点不是让每一次矩阵乘都更小，而是让一次大模型调用同时“覆盖”更多未来 token。

Baseline / serial dependency

标准解码的时间形状

论文 §1
x₁ → x₂ → x₃ → … → xK
K tokens = K serial runs of Mp

第 t 步依赖前面的 prefix，不能简单把 K 次调用全部并行化。论文进一步观察到：在常见配置里，推理可能受内存带宽与通信而非算术运算限制，因此“多算一点”有机会换来“少等几轮”。

Design constraints

加速不能牺牲什么？

工程师视角
  • 输出分布不变：不是让小模型的近似分布蒙混过关，而是仍然从目标模型 Mp 的分布采样。
  • 模型不重训：使用已有 checkpoint，不改架构、不改训练流程。
  • 并行资源要够：γ+1 个目标分布的验证被假设能并行完成；没有空闲算力时，方法可能没有收益。
Where it splits from prior work

分水岭：并行候选 + 随机采样的严格验收

论文 §5
路线具体工作它解决了什么与本文的差异
自适应计算Wisdom of Committees（Schwartz et al., 2020）；early exits简单步骤少花计算通常靠启发式停止，可能改变输出；常需定制训练或架构。
块级并行Blockwise Parallel Decoding（Stern et al., 2018）一次生成多个 token只支持 greedy，需要额外训练自定义模型，目标是任务质量而非分布严格相同。
输入复制Shallow Aggressive Decoding（Sun et al., 2021）输入输出相似时并行复制只支持复制输入，不支持一般的近似模型，也不支持一般随机采样。
本文Speculative Sampling + Speculative Decoding通用 draft 提案，target 并行验证标准采样／argmax 都可纳入；分布保证不依赖 draft 好坏。
▶ 跑一遍 · 为什么“猜错”也不一定慢 示例值
  1. 设一轮 draft 长度 γ = 3，Mq 依次提出 x₁、x₂、x₃；Mp 并行计算 p₁、p₂、p₃、p₄。
  2. 若前两个候选接受、第三个拒绝，则本轮提交 x₁、x₂、t，其中 t 从修正分布 p′ 采样：一共 3 个 token。
  3. 即使第三个候选被丢弃，本轮也只增加 1 次 Mp 串行迭代；最坏情况下仍至少提交 1 个 token，不会比标准解码增加 Mp 的串行调用数。

机制依据：论文 §2.1、Algorithm 1。γ=3 与接受轨迹是帮助理解的示例，不是某条实验 trace。

02 / HLD

把一次迭代拆成两条轨

上轨是便宜的提案器 Mq，下轨是昂贵但权威的目标模型 Mp；验证器是唯一决定哪些候选能进入输出的控制点。实线是数据面，虚线是控制面。

依据论文 Algorithm 1 与 Figure 5 重绘／示意。Mp 的 γ+1 个分布评估在算法上并行；实际 kernel 的批量实现属于工程落地细节。

Serial time / optimize down
减少 Mp 串行迭代

每轮至少产出 1 个 token，最多 γ+1 个。

Parallel compute / spend
增加并发算术运算

目标模型要同时验证 γ+1 个 prefix；拒绝的候选会浪费计算。

Memory reads / potentially down
权重与 KV 读取可摊薄

论文指出它们可在一次 Algorithm 1 执行中读取一次；这不等于所有内存流量都下降。

▶ 跑一遍 · 一次 HLD 往返 γ=3 的示例轨迹
  1. prefix 同时进入 Mq 与 Mp：Mq 负责“猜”，Mp 负责“给每个位置一个权威分布”。
  2. Mq 的三次自回归调用是串行的；Mp 的四个 prefix 评估是并行的。并行的是验证，不是 draft 提案。
  3. 验证器沿候选顺序找到第一个拒绝位置，只保留它之前的连续前缀；后面的并行结果全部丢弃。
  4. commit 把 n 个已接受 draft token 与 1 个 target token 拼接，再更新 prefix，进入下一轮。
03 / Algorithm

核心流程：接受概率只是半场，修正分布才补上另一半

如果只做“按 p/q 接受”，拒绝后的处理就会改变分布。论文的关键补丁是：拒绝时从 p 与 q 的正差值重新归一化采样。

Algorithm 1 / readable pseudocode
# p and q are already standardized for the desired sampler
for i = 1 … γ:
    qᵢ = Mq(prefix + x₁…xᵢ₋₁)
    xᵢ ~ qᵢ

p₁…pγ+1 = Mp(prefix), …, Mp(prefix + x₁…xγ)  # parallel
r₁…rγ ~ U(0, 1)
n = first index where rᵢ > pᵢ(xᵢ) / qᵢ(xᵢ), minus 1
    # if no rejection: n = γ

p′ = pₙ₊₁
if n < γ:
    p′ = norm(max(0, pₙ₊₁ − qₙ₊₁))
t ~ p′
return prefix + [x₁ … xₙ, t]
▶ 跑一遍 · 三个 token 的采样修正实验室 p、q 为示例值

选一个由 q 提出的 token，再拖动随机数 r。接受规则是 r ≤ min(1, p(x)/q(x))；若拒绝，就从正差值 p′ 采样。这个例子里，β = Σ min(p,q) = 0.70。

为什么最后仍然是 p(x)？

对任意 token x′，接受路径贡献 min(p,q)，拒绝路径贡献 (1−β)p′ = p−min(p,q)。两项相加恰好是 p。这里的 β 是当前 prefix 的接受概率；论文的 α 是对 prefix 取期望后的平均接受率。

P(x = x′) = min(p,q) + [p − min(p,q)] = p(x′)
p′(x) = [p(x) − min(p(x),q(x))] / (1 − β)

依据论文 Appendix A.1。示例分布：p=(0.5,0.3,0.2)，q=(0.2,0.5,0.3)。

  1. 论文观察到：在会长序列重复的任务里，甚至“发现匹配 prefix 就复制上下文 token”的无参数 draft，也可能得到较高 α。

05 / Design decisions

五个决定，换来“快而且仍然正确”

这部分按“问题 → 被否决的备选 → 选择理由 → 代价”拆开。注意：论文的严格保证来自采样规则，不是来自 draft 模型足够聪明。

D1

先猜，再验收

把串行依赖改成可验证的并行工作

决策问题

如何减少 Mp 的串行调用，而不直接相信一个较小的近似模型？

被否决的备选

直接采用自适应早退或 Wisdom of Committees 式的启发式停止：计算可能更少，但输出保证不再是本文的严格目标。

为什么这样选

Mq 只负责提出可能需要的 prefix，Mp 仍然对每个位置做权威验证；猜得准就能一次提交多个 token。

代价／权衡

并行验证需要额外算力，拒绝候选会浪费已经完成的计算；内存带宽成为瓶颈时更有吸引力。

D2

接受 + 残差修正

Speculative Sampling 的分布守恒核心

决策问题

如何从 q 采样，却让最终 token 严格服从 p？

被否决的备选

经典 rejection sampling，或拒绝后直接从原始 p 重采。Appendix A.2 指出后者的接受概率可能明显更低。

为什么这样选

以 min(1,p/q) 接受，再以 norm(max(0,p−q)) 修正；接受质量与拒绝质量拼回 p，且不需要迭代重试。

代价／权衡

必须拿到同一 prefix 下的 p、q 两个完整分布，并在拒绝位置做正差值归一化；实现不能省略 q 的保存。

D3

先标准化采样，再谈算法

把 argmax、top-k、nucleus、temperature 统一到 p/q

决策问题

如何证明一个算法适用于不同采样器，而不是只适用于 multinomial sampling？

被否决的备选

在 logits 层为每种采样策略分别写一套 speculative 逻辑；Blockwise Parallel Decoding 的 greedy-only 路线也不覆盖一般随机设置。

为什么这样选

论文把各种采样先视为“从调整后的概率分布标准采样”。argmax 也可表示为非最大项置零再归一化，于是同一个验收规则复用。

代价／权衡

Mp 与 Mq 必须使用一致的概率标准化；论文实验中 LaMDA 还固定经过 Top 40 filter，细节不能被 Logits 原始值掩盖。

D4

draft 不必越大越好

在 α 与成本系数 c 之间找平衡

决策问题

更强的 draft 能提高接受率，但是否一定带来更低延迟？

被否决的备选

盲目选最大的 T5-large，或立刻投入定制蒸馏、early-exit、架构修改等路线。

为什么这样选

论文发现小约两个数量级的现成模型通常最划算。EnDe、T=0、γ=7 时，T5-small 的 α=.75 却跑出 3.4×，高于 T5-large 的 α=.82、1.7×。

代价／权衡

draft 太小会 α 低、浪费验证；draft 太大会 c 高、吃掉并行收益。α 是模型／任务属性，c 还依赖硬件与实现。

D5

先固定 γ，再把动态化留作下一步

一个可部署的整数旋钮

决策问题

每轮猜多少 token，才能在长候选的收益与 draft／验证成本之间取得最大速度？

被否决的备选

固定凭直觉取 γ，或假设有一个能预知每个 prefix 接受率的 oracle 来动态改变 γ。

为什么这样选

给定 α、c，直接数值搜索整数 γ 即可优化 Theorem 3.8；不引入额外预测器，便于复现与部署。

代价／权衡

真实 β 会随 prefix 变化，固定 γ 不是理论上最优。论文估计 oracle 上界在典型设置下最多再带来约 60% 改善，但留作未来工作。

D6

默认严格，lenience 显式另算

速度旋钮不能偷偷改写正确性目标

决策问题

如果愿意放宽输出分布，能否继续提高接受率？

被否决的备选

把 Appendix A.5 的 lenience 当成主算法的免费加速；那会让“分布不变”这个核心承诺失效。

为什么这样选

主结果全部使用最严格的 Algorithm 1；lenience 单独给出概率上界，例如 l=.1 时，任何 token 的概率不会超过真实 p 的 10 倍。

代价／权衡

放宽后速度可更高，但不保证最低概率，可能损害样本多样性；argmax 还需要另一种 lenience 定义。

07 / Critical reading

它改变的是时间形状，不是计算守恒律

最值得带走的不是“给所有模型加一个小模型”，而是一种系统分解：把便宜的猜测、昂贵的验证和严格的纠偏放在同一条可观测的流水线上。

What the paper itself bounds

论文自认的局限

§3、§6、Appendix
  • 需要空闲并行资源：如果系统已经算力 bound，增加并发不会带来同样的 walltime 收益。
  • 总算术运算可能上升：被拒绝的猜测是浪费；论文的加速建立在用并发换串行时间。
  • i.i.d. 只是分析假设：不同 prefix 的 β 会变化，理论预测与实测存在偏差。
  • 实验范围有限：实际 walltime 实现主要针对 T5；GPT-like 与 LaMDA 部分主要是 α 测量，论文也只测试文本模态。
  • 还有未完成的扩展：beam search 的组合条件更复杂；动态 Mq／γ、层级 draft、其他模态都留作后续方向。
Questions an engineer should ask

读者应该继续追问

工程师视角
  • 吞吐还是单请求延迟？论文的关键实测是 batch=1；大 batch 已经吃满硬件时，额外验证是否仍有空位，需要重新测量。
  • “同分布”不等于“同随机种子同序列”：随机采样保证的是分布守恒；不要把它误读为每次运行都逐 token 重现同一随机轨迹。
  • c 在你的部署里是多少？它依赖硬件、kernel、通信与实现，不能照搬 TPU-v4 的估计。
  • 验证的并行是否真的没有墙钟代价？这是 Theorem 3.8 的简化假设；长 prefix、KV cache 与调度开销需要在目标系统上复核。
  • 采样标准化是否一致？top-k、nucleus、temperature、Top 40 等变换必须对 p/q 以相同语义处理。
Transferable ideas

可以直接偷的思想

工程师视角
  • 把“提议”和“裁决”分开：便宜的模块可以大胆猜，昂贵的模块只在权威节点验收。
  • 把正确性写进采样器：不要靠 draft 质量兜底；用接受概率与残差分布把误差闭环。
  • 先试零成本 draft：n-gram、上下文复制等无参数方法部署简单，在重复文本场景值得做 baseline。
  • 把 γ 当成可测量旋钮：用 α、c 做初始数值搜索，再用真实 trace 校准，而不是盲目增大候选长度。
  • 与其他优化叠加评估：量化、稀疏化等改善内存／算力比的技术，可能与 speculative decoding 互补，但组合后的瓶颈要重新定位。
▶ 跑一遍 · 构造一个“会更慢”的参数组合 示例值，非论文实测
  1. 取 α=.40、γ=8、c=.20，仍使用论文 Theorem 3.8 的理想化模型。
  2. 期望 token 数 = (1−.4⁹)/(1−.4) ≈ 1.6661。
  3. 理论速度 = 1.6661/(8×.20+1) ≈ 0.641×：不是加速，而是约 36% 的时间增加。
  4. 这正是论文限制条件的直观版本：接受率不够高、draft 又不够便宜时，额外计算会把收益吃光。
One-sentence takeaway

Speculative Decoding 用“多余但并行的计算”购买“更少的串行等待”，并用一个可证明的残差采样器确保你买到的仍然是 Mp 的分布。

论文结论 在给定算力与内存带宽瓶颈的前提下，T5 实验展示了 2–3× 的实际收益；工程师视角 真正的部署门槛是：测出你的 α、c、并行余量，再决定这套机制是否值得上线。

Source paper
Yaniv Leviathan, Matan Kalman, Yossi Matias. Fast Inference from Transformers via Speculative Decoding. Proceedings of ICML 2023, PMLR 202; arXiv:2211.17192v2, 18 May 2023. 本报告基于用户提供的 13 页 PDF，所有重绘图均在图注标明。
