00 · The contract

One job: predict what comes next.

A decoder-only language model receives token IDs shaped [batch, time] and returns one score for every vocabulary item at every time step: [batch, time, vocab].

Original diagram. Each position predicts its next token; generation repeats that same forward pass one token at a time.

The training objective and the generation procedure are the same mechanism viewed from opposite sides. During training, the correct next token is known. During generation, we select one candidate, append it, and ask again.

A logit is an unrestricted score, not yet a probability. If the vocabulary has 258 entries, every position emits 258 logits. Softmax turns one row of those scores into probabilities only when the loss or decoder needs them. Keeping logits unnormalized inside the model is both numerically convenient and exactly what PyTorch's cross-entropy expects.

The phrase “from scratch” has two meanings here. Architecturally, every learned component is instantiated with fresh random weights: embeddings, attention projections, feed-forward layers, normalizations, and the language-model head. Operationally, the example also avoids hidden assets: its corpus is embedded in train.py, its tokenizer has no downloaded vocabulary, and its tests run without a network connection. That gives us a controlled laboratory for the mechanics, not a shortcut to the data and compute used by a production LLM.

A forward pass in plain language

Suppose the input ends with “the model”. Token and position embeddings first say what each token is and where it occurs. Every transformer block then lets a position gather useful information from earlier positions and transform the resulting features. The final vector at the last position summarizes the prefix; the output head scores every possible next byte. Training compares all positions with known next bytes at once. Generation uses only the final row, appends the chosen byte, and repeats.

Scope checkThis model is intentionally tiny and the byte tokenizer is intentionally simple. The architecture is real; the learned language ability is not meant to be useful. Keeping those two claims separate is the first reproducibility rule.
01 · Tokens and targets

Text must become integers before it can become vectors.

Production GPT-family models usually use a subword tokenizer. Our offline smoke path uses raw UTF-8 bytes: IDs 0–255 plus explicit end-of-sequence and padding IDs.

[B,T]integer token IDs entering the model
[B,T,D]token + position embeddings
[B,T,V]vocabulary logits leaving the model

Why bytes are useful here—and poor for scale

A byte tokenizer has an unusually clean contract: encode text as UTF-8 bytes and decode those bytes back to text. There is no learned vocabulary, unknown-token case, or external tokenizer file. ASCII characters occupy one token each, while many non-ASCII characters occupy several. That makes byte sequences longer than modern subword sequences, so attention does more work for the same passage. We accept that inefficiency because the example is small and the reversible mapping is easy to inspect.

Two reserved IDs sit above the 256 byte values. EOS marks the end of a document or generated sequence; PAD makes unequal examples fit a rectangular batch. They are different semantic events. EOS is a target the model should learn to predict. Padding is bookkeeping and its labels should be ignored by the loss.

The shift is the supervision

Take one sequence of T+1 token IDs. The first T are inputs; the last T are targets. No label file is required.

tokens: [10, 11, 12, 13, 14]
inputs: [10, 11, 12, 13]   targets: [11, 12, 13, 14]At time t, the model sees tokens ≤ t and is graded on token t+1.
examples/llm/data.py · exact executable excerpt
window = token_ids[start : start + context_length + 1]
pairs.append(
    (
        torch.tensor(window[:-1], dtype=torch.long),
        torch.tensor(window[1:], dtype=torch.long),
    )
)

Sliding windows reuse a corpus efficiently. With context length 32, a 33-token window yields 32 next-token decisions. Moving the window by a stride smaller than 32 creates overlapping examples; moving by 32 creates disjoint chunks. Overlap increases the number of training pairs but does not create new information, so train/validation splitting must happen at the document level before windows are made. Otherwise near-identical windows can land on both sides of the split and make validation look better than it is.

Embeddings supply content and order

The token embedding table has shape [V,D]; indexing it with [B,T] IDs returns [B,T,D]. A learned position table has shape [context_length,D]. Broadcasting adds the same position vector to every example in a batch. Without positional information, self-attention can see which tokens are present but cannot distinguish “dog bites person” from “person bites dog” purely from order.

Classic silent failureIf inputs and targets are identical, the model is trained to reconstruct the current token instead of predict the next one. Our smoke test asserts the exact shifted lists.
02 · Causal attention

Each token may look left, never right.

Self-attention creates content-dependent mixtures. Causality keeps training honest by removing information that would not exist during generation.

scores = (Q @ Kᵀ) / √Dₕ
weights = softmax(mask(scores))
context = weights @ VIn code: scores [B,H,T,T], weights [B,H,T,T], V [B,H,T,Dh].

Three learned linear projections turn each hidden vector into a query, key, and value. A query represents what the current position is looking for; keys represent what earlier positions offer; values contain the information to mix. The query–key dot product produces a compatibility score. Dividing by √Dh keeps those dot products from growing with head width and pushing softmax into extremely sharp, low-gradient regions.

Follow one tensor through the heads

Starting from x [B,T,D], one projection produces the Q, K, and V features. Each is reshaped to [B,T,H,Dh] and transposed to [B,H,T,Dh], where D = H×Dh. Multiplying Q by K-transpose gives one [T,T] score matrix per batch item and head. After masking and softmax, multiplying by V restores [B,H,T,Dh]. Transpose, concatenate the heads, and the output projection returns [B,T,D], ready for the residual addition.

Original diagram. Masking happens before softmax; the forbidden upper triangle then receives exactly zero probability.
examples/llm/model.py · exact executable excerpt
scores = q @ k.transpose(-2, -1) / self.head_dim**0.5  # [B,H,T,T]
allowed = self.causal_mask[:, :, :tokens, :tokens]
scores = scores.masked_fill(~allowed, float("-inf"))
weights = self.dropout(F.softmax(scores, dim=-1))
context = weights @ v  # [B,H,T,Dh]

The mask is lower-triangular: row t allows columns 0…t. It is applied to scores with negative infinity before softmax, making forbidden probabilities exactly zero. Masking after softmax would leave the remaining probabilities summing to less than one unless they were renormalized, and it would be easier to leak future information through an incorrect implementation.

Multiple heads do not create separate timelines. They are parallel learned views over the same prefix: one head may become sensitive to nearby syntax while another tracks a longer dependency. That interpretation is suggestive rather than guaranteed—heads are optimized jointly, and a trained head need not have a clean human label.

  • Scale by √Dh, not by model width or token count.
  • Mask logits before softmax, not probabilities afterward.
  • Test both invariants: future entries are zero and every allowed row sums to one.
03 · The GPT block

Mix across time, then mix across features.

A transformer block has two distinct communication paths. Attention moves information between token positions. The feed-forward network transforms each position independently.

Normalize, attend, add the shortcut

Pre-normalization stabilizes the input to attention. The residual path keeps an identity route for signals and gradients.

Normalize, expand, activate, contract

The MLP maps D → 4D → D with GELU, then adds a second shortcut.

Repeat L times, normalize, project to vocabulary

The language-model head converts every contextual vector into V logits.

This implementation uses pre-normalization: LayerNorm comes before each attention or MLP sublayer. The residual stream itself remains a direct route through the network, which usually makes optimization of deeper decoders easier than placing normalization only after the addition. LayerNorm operates across the feature dimension of each token independently, so it neither mixes examples nor allows future tokens to communicate.

The MLP deserves more credit than its simple shape suggests. Attention decides where to retrieve information; the MLP provides most of the block's feature-wise nonlinear capacity. Expanding from D to 4D, applying GELU, and contracting back lets every position build combinations that a stack of linear projections alone could not express.

examples/llm/model.py · block and top-level data flow
def forward(self, x: torch.Tensor) -> torch.Tensor:
    x = x + self.attention(self.attention_norm(x))
    return x + self.mlp(self.mlp_norm(x))

# MiniGPT.forward
x = self.token_embedding(token_ids) + self.position_embedding(positions)
for block in self.blocks:
    x = block(x)
logits = self.lm_head(self.final_norm(x))  # [B,T,V]

Residuals make the block learn a change

In x + attention(...), the sublayer does not have to reconstruct its entire input; it can learn a useful correction. The same is true for the MLP. During backpropagation, these additions also provide short gradient paths. Dropout regularizes the learned branch during training and becomes an identity operation in evaluation mode, which is why switching modes is part of correct measurement.

The input embedding and output head share one weight matrix. Input lookup reads rows from it; output projection compares hidden states against all rows. Weight tying reduces parameters and gives the two ends of the model a common token geometry. Initialization happens once before the shared reference is assigned, avoiding an accidental second randomization of that matrix.

Shape and parameter lab

The calculator is an estimate for intuition; count_parameters(model) is the authority for the executable configuration. Position embeddings grow with context length, while attention compute and its score matrix grow roughly with T².

For the shipped configuration—width 48, two blocks, four heads, context 32—the exact trainable count is 70,560. The number is tiny enough for CPU tests, yet all important ranks and boundaries match a larger decoder. Scaling the width is especially expensive: the attention and MLP projection matrices grow roughly with D², while the attention score memory grows with T².

04 · Pretraining

Cross-entropy turns next-token guesses into a learning signal.

For each of the B×T positions, cross-entropy rewards the logit assigned to its target token and penalizes probability placed elsewhere.

loss = − (1 / N) Σ log softmax(logitsᵢ)[targetᵢ]N = B×T after flattening. Lower is better; perplexity is exp(loss).
examples/llm/model.py · the exact loss boundary
loss = F.cross_entropy(
    logits.reshape(batch * tokens, -1),
    targets.reshape(-1),
    ignore_index=-100,
)

Flattening changes only the view of the data: [B,T,V] becomes [B×T,V], and [B,T] targets become [B×T]. Cross-entropy internally applies log-softmax and selects the target column, so applying softmax in the model would be redundant and less stable. An initial loss near log(V) is plausible for nearly uniform predictions; with V=258, that reference is about 5.55—the observed starting value.

What one optimizer step changes

zero_grad clears gradients accumulated by earlier batches. The forward pass produces logits and loss. backward follows the computation graph from that scalar to every parameter that influenced it. Gradient clipping caps the combined norm so an unusual batch cannot cause a huge update. AdamW then uses running moment estimates plus decoupled weight decay to change the parameters. None of these steps stores “the sentence” in a special location; learning is distributed across matrices.

The training loop is deliberately ordinary: clear gradients, run the model, backpropagate, clip the global gradient norm, update AdamW. Evaluation must switch to model.eval() and torch.no_grad(); otherwise dropout noise and an unnecessary graph contaminate measurement.

SplitPurposeCommon leakage

A falling tiny-corpus loss proves plumbing, not intelligence.It tells us gradients reach parameters and the model can fit data. It does not establish factuality, reasoning, safety, or performance on unseen text.

Perplexity, exp(loss), can be read as an effective number of equally likely next-token choices under the model, but only when comparing the same tokenizer and evaluation data. Byte and subword tokenizers divide text differently, so their per-token perplexities are not directly comparable. Always report the data split and tokenization alongside the number.

05 · Generation

One forward pass becomes a loop.

At each step, crop to the model’s context window, run the model, keep the last position’s logits, choose one token, and append it.

examples/llm/model.py · simplified excerpt; top-k branch omitted
context = token_ids[:, -self.config.context_length :]
logits, _ = self(context)
next_logits = logits[:, -1, :]
if temperature == 0:
    next_id = next_logits.argmax(dim=-1, keepdim=True)
else:
    probabilities = F.softmax(next_logits / temperature, dim=-1)
    next_id = torch.multinomial(probabilities, num_samples=1)
token_ids = torch.cat((token_ids, next_id), dim=1)

Greedy decoding is deterministic but can repeat. Temperature controls distribution sharpness; it does not improve the model. Top-k removes the long tail before sampling. These are selection policies over learned logits, not extra reasoning layers.

Temperature zero is handled as a separate argmax path; dividing by zero would be undefined. For positive temperature, values below one sharpen the distribution and values above one flatten it. Top-k then retains only the k largest logits and sets the rest to negative infinity before softmax. The order matters because filtering probabilities after normalization requires another normalization pass.

Generation also exposes the fixed context limit. Once the sequence is longer than 32 tokens, this example feeds only the newest 32 back into the model. Older information is no longer visible. A production system may use a much longer context and a key/value cache to avoid recomputing earlier states, but neither changes the causal next-token contract demonstrated here.

Finally, stopping is a policy decision. This compact loop always ends after max_new_tokens; production decoders commonly stop a sequence when it emits EOS as well. If a tiny, undertrained model generates spaces or fragments, that is an honest result: sampling cannot manufacture knowledge that training did not put into the logits.

06 · Instruction tuning

Same model, different sequence and loss mask.

Supervised instruction fine-tuning (SFT) does not replace next-token prediction. It formats task/response examples into sequences and chooses which positions should contribute to the same cross-entropy loss.

### Instruction: Add 1 + 1.

### Response:
2 <EOS>Inputs remain a single token stream. Labels over prompt and padding positions become -100, PyTorch’s ignored target.
examples/llm/data.py · response-only target boundary
inputs = full_ids[:-1]
labels = full_ids[1:]
# Label prompt_len-1 predicts the first response token and must be kept.
labels[: max(0, len(prompt_ids) - 1)] = [-100] * max(
    0, len(prompt_ids) - 1
)

The off-by-one matters: label position prompt_len−1 is produced from the prompt’s final token and predicts the response’s first token. Mask it and the model never learns how to begin answering.

SFT changes behavior, not the architecture

Pretraining learns broad continuation statistics from plain text. SFT presents a narrower distribution in which instructions are followed by desired responses. The weights, causal mask, and language-model head are unchanged; only the serialized examples and which labels receive loss differ. That is why a pretrained checkpoint is normally the starting point: a small instruction dataset can shape an existing language model, but cannot efficiently teach language from nothing.

Padding introduces a second masking boundary. Suppose two examples have different lengths. Their token tensors are padded to a common T, but target positions created solely by padding must also be -100. Otherwise the optimizer is rewarded for predicting PAD repeatedly. Here padding is added only on the right, so causality prevents every real token from seeing it and ignored labels remove the padded positions from loss. More complex packing or left-padding schemes need an explicit attention-padding mask too.

Response-only masking answers a precise question: “Given this prompt, how should the assistant continue?” It does not train the model to reproduce the prompt. Some chat systems intentionally include loss on selected system or user tokens, and multi-turn templates may mask each role differently. The safe engineering habit is to inspect a tokenized example and its labels, especially the first response token and EOS, instead of trusting a template by inspection.

There is no universal masking rule.Some recipes also train on instruction tokens; others isolate response loss. Here we choose response-only supervision so the boundary is visible and testable, not because it is always superior.

How to read the smoke run

The JSON output is intentionally modest. parameters checks that configuration and weight tying produced the intended model. initial_loss is measured before updates; final_loss uses the same embedded corpus after training. With the fixed seed, 20 CPU steps reproduce 5.5538→2.7768, and 60 steps reach about 1.58 in the recorded environment. Exact floating-point tails can differ across PyTorch versions and devices, so the test suite locks structural invariants rather than one training number.

If the loss becomes NaN, first inspect learning rate, target range, and whether a fully masked attention row reached softmax. If the loss falls but generation is nonsense, check tokenizer round-tripping, the shifted target boundary, train/eval mode, and whether the tiny corpus contains enough context for the prompt. Those checks localize most from-scratch failures faster than tuning the architecture.

Device support does not imply bit-for-bit identical training. Random-number generators, kernels, and reduction order can differ. The contract is that the code executes, shapes and masking invariants hold, gradients remain finite, and loss trends downward on the embedded corpus. CPU is the reference path; MPS was sanity-checked locally, while CUDA could not be executed in this environment.

Sources and limits

What this tutorial adapts — and what it changes.

The conceptual sequence follows Sebastian Raschka’s Build a Large Language Model (From Scratch), especially chapters 2–5 and 7, together with the official companion repository inspected at commit ef9fbc2. All prose, diagrams, and executable teaching code here are original or compact adaptations documented in notes/llm-source-ledger.md.

Differences are deliberate: byte tokens instead of GPT-2 BPE, 70k rather than 124M parameters, an embedded micro-corpus, tied input/output weights, and response-only SFT labels. This makes correctness observable offline, but it is not a recipe for a capable general-purpose model.
